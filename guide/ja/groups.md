# コンシューマーグループ

コンシューマーグループは、トピックの読み取りを分担するコンシューマーの集まりです。Kafkaは各パーティションをグループの1つのメンバーに割り当て、パーティションごとにグループがコミットしたオフセットを保存します。アプリケーションは再起動後、そのオフセットから読み取りを続けます。

**接続**パネルの接続の下にある**コンシューマーグループ**を開きます。1つのトピックのグループは、トピックの**コンシューマーグループ**タブにも表示されます。[トピック画面](topics.md#topic-details)を参照してください。

<a id="group-list"></a>

## グループ一覧

一覧には、クラスターのすべてのコンシューマーグループが表示されます。列は次のとおりです：

- **グループ**：グループID（`group.id`）。
- **状態**：Kafkaが報告する状態。たとえば、`Stable`（メンバーが読み取り中）、`Empty`（メンバーなし）、`PreparingRebalance`または`CompletingRebalance`（パーティションを再配分中）、`Dead`（グループがもう存在しない）。
- **メンバー**：アクティブなメンバーの数。
- `Assignor`：パーティションの分配に使われる戦略。例：`range`。
- **ラグ**：グループのラグの合計。[ラグ](groups.md#lag)を参照してください。
- **トピック**：グループがオフセットをコミットしたトピック。

**グループを検索**に入力すると、IDにそのテキストを含むグループが表示されます。大文字と小文字は区別されません。その横の状態の一覧では、1つの状態のグループだけを表示できます。**すべての状態**を選ぶと、この絞り込みが解除されます。カウンターには、表示中のグループ数と全体のグループ数が表示されます。

メンバー、アサイナー、ラグは、スクロールに合わせて表示中の行についてだけ読み込まれます。読み込まれるまで、セルには`…`が表示されます。読み込めなかった場合はセルに`—`が表示され、ポインターを合わせると理由がわかります。

**更新**は、一覧とその中のデータを再読み込みします。応答しなかったブローカーがある場合は、一覧が不完全な可能性があるという警告が表示されます。

<a id="lag"></a>

## ラグ

ラグとは、グループがまだ読み取っていないメッセージの数です。パーティションごとに、ログの末尾からコミット済みオフセットを引いた値です。ラグが0未満で表示されることはありません。

ラグはコミット済みオフセットだけで決まります。アクティブなコンシューマーはコミットした位置より先まで読み取っていることがあるため、実際のラグはもっと小さい場合があります。グループが再びコミットすると、ラグは減ります。

コミット済みオフセットがないパーティションには**コミットなし**と表示され、合計には含まれません。グループのラグの合計は、グループにコミットがまったくない場合（**コミットなし**）や、いずれかのパーティションのオフセットを読み取れなかった場合（**ラグ不明：パーティションのオフセットのエラー**）に`—`と表示されます。

ラグはメッセージではなくオフセットを数えます。コンパクションやトランザクションを使うトピックでは、表示されるメッセージを持たないオフセットがあるため、グループが読み取るべき残りのメッセージはラグの値より少ないことがあります。

値は読み込んだ時点のスナップショットです。ラグを追跡するには、グループを開いて自動更新をオンにします。

<a id="group-details"></a>

## グループの詳細

一覧でグループをクリックすると、そのタブが開きます。上部の概要には、状態、メンバー数、アサイナーが表示されます。

- **自動更新**：**自動更新：オフ**、**5秒ごと**、**10秒ごと**のいずれか。
- **更新**：すぐに再読み込みします。
- **メンバーとして読み取る**：このグループで[コンシューマーセッション](consumer-sessions.md)を開始します。セッションのフォームには、グループIDと、グループがコミットを持つトピックが入力されます。**読み取り専用**の接続ではボタンが無効になります。ボタンにポインターを合わせると理由が表示されます。

**パーティション**には、グループがコミットを持つパーティションと、メンバーに割り当てられたパーティションが一覧表示されます。グループのラグの合計はテーブルの上に表示されます。列は、**トピック**、**パーティション**、`Committed`（コミット済みオフセット）、`Log end`（パーティションの末尾のオフセット）、**ラグ**、**メンバー**（パーティションを読み取るメンバーのクライアントID）です。

**メンバー**には、アクティブなメンバーが一覧表示されます：`Client ID`、**ホスト**、`Member ID`、**割り当て**（メンバーのパーティションを`topic:partition`の形式で表示）。メンバーのいないグループには**アクティブなメンバーなし**と表示されます。

2行目には**オフセットをリセット**と**グループを削除**があります。読み取り専用の接続では、この行は表示されません。

<a id="reset-offsets"></a>

## オフセットのリセット

オフセットをリセットすると、グループのコミット済みオフセットが移動します。その結果、グループはメッセージを読み直すか、スキップします。オフセットをリセットできるのは、アクティブなメンバーのいないグループ（状態が`Empty`または`Dead`）だけです。そうでないと、メンバーが自身のコミットで新しいオフセットを上書きしてしまいます。先にグループのアプリケーションを停止してください。

1. グループのタブで**オフセットをリセット**をクリックします。グループにメンバーがいる間はボタンが無効です。ボタンにポインターを合わせると理由が表示されます。
2. **方法**を選びます。[リセットの方法](groups.md#reset-strategies)を参照してください。
3. **対象**を選びます。[リセットの対象](groups.md#reset-scope)を参照してください。
4. **プレビュー**をクリックします。
5. テーブルを確認し、適用ボタンをクリックします。ボタンには変更されるパーティションの数が表示されます。

プレビューでは何も変更されません。パーティションごとに、トピック、パーティション、**現在**（コミット済みオフセット）、**変更後**（目標オフセット）、`Low / High`（パーティションの最初と末尾のオフセット）が表示されます。目標を計算できないパーティションには**目標オフセットがないため、適用されません**と理由が表示されます。そのようなパーティションはスキップされます。

適用されるのは、プレビューに表示された計画だけです。フォームを変更するとプレビューは非表示になり、もう一度**プレビュー**をクリックする必要があります。本番接続では適用時に接続名の入力を求められ、それ以外の接続ではすぐに適用されます。

適用の前に、アプリはグループにメンバーがいないことを改めて確認します。適用後、**リセットの結果**に、各パーティションの新しいオフセットまたはエラーが一覧表示されます。

メッセージからリセットを準備することもできます。[グループをメッセージの位置にリセットする](browse.md#reset-group-here)を参照してください。**閉じる**をクリックすると、リセットのパネルが閉じます。

<a id="reset-strategies"></a>

## リセットの方法

**方法**は、対象の各パーティションの目標オフセットを決めます：

- **先頭から（earliest）**：まだ保存されている最初のオフセット。グループは、トピックに保持されているすべてのメッセージを読み直します。
- **末尾から（latest）**：パーティションの末尾。グループは溜まったメッセージをすべてスキップし、新しいメッセージだけを読み取ります。
- **時刻で指定**：「**日時（ローカル）**」で指定した日時以降に書き込まれた最初のメッセージ。それより新しいメッセージがないパーティションでは、目標は末尾になります。
- **オフセットを指定**：すべてのパーティションで、指定した**オフセット**（0以上の整数）。パーティションにそのオフセットがない場合、目標はそのパーティションの最初または末尾のオフセットになります。
- **±Nシフト**：コミット済みオフセットを「**シフト（±N）**」の値だけ動かします。負の数ではN件前から読み直し、正の数ではN件スキップします。結果は最初と末尾のオフセットの範囲内に収まります。コミット済みオフセットがないパーティションはシフトできず、スキップされます。

時刻はローカル時刻で、秒まで指定します。Kafkaはメッセージのタイムスタンプからオフセットを探します。

<a id="reset-scope"></a>

## リセットの対象

**対象**は、どのパーティションをリセットするかを決めます。それ以外のパーティションのオフセットはそのまま残ります。

- **グループ全体**：グループがオフセットをコミットしたすべてのパーティション。グループにまだコミットがない場合は、代わりにトピックを選んでください。
- **トピック**：指定したトピックのすべてのパーティション。コミットのないパーティションも含みます。名前はコンマ、スペース、改行で区切ります。グループに新しいトピックを指定した位置から読み取らせたい場合に使います。
- **パーティション**：指定したパーティションだけ。「**パーティション（topic:partition）**」に`topic:partition`の形式で、コンマまたはスペースで区切って入力します。例：`orders:0, orders:3`。

<a id="delete-group"></a>

## グループを削除する

グループを削除すると、そのコミット済みオフセットがすべて削除されます。削除できるのは、メンバーのいない`Empty`状態のグループだけです。

1. グループのタブで**グループを削除**をクリックします。グループにメンバーがいる間はボタンが無効です。ボタンにポインターを合わせると理由が表示されます。
2. 確認のためにグループIDを入力します。本番接続では、接続名も入力します。
3. **削除**をクリックします。

削除すると、グループのタブが閉じます。この`group.id`を持つアプリケーションが再び起動すると、Kafkaはグループを新たに作成します。コミット済みオフセットがないため、アプリケーションは`auto.offset.reset`の設定に従って、先頭または末尾から読み取りを始めます。

**読み取り専用**の接続では、このボタンは表示されません。
