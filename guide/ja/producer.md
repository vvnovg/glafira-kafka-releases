# Producer

**Producer**は、Kafkaにメッセージを送信します。フォームから1件ずつ送信することも、まとめて送信することもできます。**接続**パネルの接続から開くか、トピックのタブの**メッセージを送信**から開きます。後者の場合はトピックが入力されます。Producerのタブは接続ごとに1つです。

**読み取り専用**の接続では、Producerを開くと「**接続は読み取り専用のため、送信できません。**」という警告が表示されます。送信ボタンは非表示になりますが、テンプレートと履歴は引き続き閲覧できます。

<a id="send-message"></a>

## メッセージを送信する

1. **トピック**を入力します。フィールドには、内部トピックを除くクラスターのトピックが候補として表示されます。
2. 必要に応じて、**パーティション**の番号を入力します。フィールドに**自動**と表示されている場合、パーティションはキーによって選ばれます。Javaクライアントと同様に、同じキーのメッセージは同じパーティションに送られます。キーのないメッセージはランダムなパーティションに送られます。
3. **キー**と**値**を入力し、それぞれの形式を選びます。[キーと値の形式](producer.md#key-value-formats)を参照してください。
4. 必要に応じて、ヘッダーを追加します。
5. **送信**をクリックします。

送信に成功すると、フォームの下の行にメッセージのパーティション、オフセット、時刻が表示されます。`acks`が`0`の場合、ブローカーはオフセットを返さないため、代わりに`—`が表示されます。

パーティション番号が大きすぎる場合や、接続のタイムアウト内にブローカーがメッセージを確認しない場合は、エラーが表示されます。存在しないトピックもエラーになります。ただし、ブローカーがトピックを自動作成する設定（`auto.create.topics.enable`）の場合は除きます。自動作成がオフの場合、このエラーが表示されるまで最大で約30秒（接続のタイムアウト）かかることがあります。無効なJSONや不明なプレースホルダーなど、フォームのエラーは送信前に表示されます。

本番接続では、送信時に接続名を入力して**本番に送信**で確定するよう求められます。[環境と本番](connections.md#environments)を参照してください。

**フォームをクリア**はフォームを空にし、プロデューサーの設定をデフォルトに戻します。トピックはそのまま残ります。

<a id="key-value-formats"></a>

## キーと値の形式

**キーの形式**と**値の形式**は、フィールドのテキストをバイトに変換する方法を指定します：

- `string`：テキストをそのままUTF-8で送信します。
- `json`：テキストが有効なJSONであることを確認し、整形せずに入力どおり送信します。
- `hex`：1バイトにつき2桁の16進数。例：`48656c6c6f`。スペースと改行は無視されます。
- `base64`：標準のBase64で表したバイト。
- `null`：キーまたは値そのものがありません。フィールドは空で、テキストを入力すると形式が`string`に切り替わります。

デフォルトは、キーが`null`、値が`json`です。キー付きのメッセージを送信するには、キーを入力するだけです。形式は自動的に`string`に変わります。空の文字列もキーであり、キーがないこととは異なります。`string`を選んでフィールドを空のままにすると、そのようなメッセージはすべて同じハッシュになり、1つのパーティションに送られます。

値が`null`のメッセージはtombstoneです。`cleanup.policy=compact`のトピックでは、同じキーを持つ古いメッセージを削除するようKafkaに伝えます。

<a id="headers"></a>

## ヘッダー

ヘッダーは、メッセージとともに送信される名前と値のペアです。**ヘッダーを追加**をクリックして行を追加し、**名前**、**値**、**形式**を入力します。`×`ボタンで行を削除します。

ヘッダーの値の形式は、`string`（UTF-8のテキスト）または`hex`（バイトを16進数で表記）です。名前が空の行は送信されません。Kafkaでは同じ名前のヘッダーを複数持つことができ、それらはすべて送信されます。

プレースホルダーはヘッダーの値では使えますが、ヘッダーの名前では使えません。

<a id="placeholders"></a>

## プレースホルダー

プレースホルダーは、送信のたびに値に置き換えられます。キー、値、ヘッダーの値で使えます。一覧はヘッダーの下に表示されます：

- `{{uuid}}`：新しいランダムなUUID。例：`0b6f6f2c-3c1e-4a8e-9a54-2f0d6f1d7c21`。
- `{{now}}`：現在時刻（UTC）。ミリ秒付きのISO 8601形式。例：`2026-10-15T12:30:00.000Z`。
- `{{nowMillis}}`：1970-01-01 UTCからの現在時刻（ミリ秒）。
- `{{seq}}`：一括送信でのコピーの番号。0から始まります。1件だけ送信する場合は`0`です。
- `{{randomInt 1 100}}`：2つの数値の間のランダムな整数。両端を含みます。
- `{{randomString 8}}`：指定した長さ（最大100000）の、半角英字と数字からなるランダムな文字列。
- `{{env NAME}}`：環境変数`NAME`の値。設定されていない場合は何も送信されず、エラーが表示されます。

波かっこの内側にはスペースを入れられます。不明なプレースホルダーや`}}`の欠落があると、エラーになり送信が止まります。`{{`をテキストとして送信するには、`\{{`と書きます。

`json`形式では、プレースホルダーが置き換えられたあとにJSONが確認されます。テキストを生成するプレースホルダーには引用符が必要です：`{"id": "{{uuid}}"}`。数値には不要です：`{"n": {{seq}}}`。

`{{env NAME}}`は、Glafiraのプロセスの環境変数を読み取ります。DockやスタートメニューからGlafiraを起動した場合、ターミナルのプロファイルだけで設定した変数は存在しないことがあります。

[Producerで開く](browse.md#open-in-producer)や履歴から取り込んだメッセージでは、すべての`{{`が`\{{`として書かれます。そのため、メッセージは何も置き換えられずに元のとおり送信されます。

<a id="templates"></a>

## テンプレート

テンプレートには、トピック、パーティション、キー、値、ヘッダー、形式、プロデューサーの設定など、フォーム全体が保存されます。プレースホルダーは書かれたとおりに保存され、送信のたびに置き換えられます。

テンプレートを保存するには、**テンプレートとして保存**をクリックし、**テンプレート名**を入力して**保存**をクリックします。トピックは空でもかまいません。デフォルトでは、テンプレートはこの接続に属します。すべての接続で表示するには**すべての接続で使用**を選択します。そのようなテンプレートには、一覧で「**（すべての接続）**」と表示されます。

テンプレートを使うには、**テンプレート**の一覧から選びます。フォームはテンプレートの内容に置き換えられます。送信前にフォームを編集しても、テンプレートは変わりません。

保存すると常に新しいテンプレートが作成されます。テンプレートを変更するには、読み込んでフォームを編集し、新しい名前で保存してから古いものを削除します。選択したテンプレートを削除するには、**テンプレートを削除**をクリックし、**削除**で確定します。

接続のテンプレートは、接続と一緒に削除されます。

<a id="history"></a>

## 履歴

「**履歴（最新100件）**」には、この接続で1件ずつ送信した最新100件のメッセージが新しい順に一覧表示されます。一括送信のメッセージは追加されません。各行には、時刻、トピック、パーティションとオフセット、キーの先頭部分が表示されます。

履歴には、プレースホルダーが置き換えられた状態で、送信したとおりのメッセージが保存されます。**再送信**をクリックすると、メッセージがプロデューサーの設定とともにフォームに読み込まれます。**送信**をクリックするまで何も送信されません。コピーは保存されたとおりに送信されます。たとえば、同じUUIDがもう一度送信されます。

64 KBを超えるキー、値、ヘッダーの値は一部だけが保存されます。そのような行では**再送信**が無効になります。

履歴は、`{{env NAME}}`の値も含めて、このコンピューターに平文で保存されます。これが問題になる場合は、Producerでシークレットを送信しないでください。接続の履歴は、接続と一緒に削除されます。

<a id="batch-copies"></a>

## フォームのコピーをN件送信

フォームの下の**一括送信**では、1回の実行で多数のメッセージを送信します。**フォームのコピーをN件**モードでは、フォームを指定した回数だけ送信します。

1. 1件だけ送信する場合と同じようにフォームに入力します。
2. **フォームのコピーをN件**を選択し、**コピー数**を1から1000000の範囲で入力します。
3. 必要に応じて、**レート**を設定します。[送信レート](producer.md#batch-rate)を参照してください。
4. **開始**をクリックします。

プレースホルダーはコピーごとに置き換えられます。`{{seq}}`は0からN−1までのコピー番号なので、メッセージごとに異なるキーを付けられます。例：`order-{{seq}}`。プレースホルダーのエラーは、実行開始前に最初のコピーで確認されます。

実行中、パネルには送信済みと失敗したメッセージの数が表示されます。終了すると**完了**と表示されます。エラーは1から数えたコピー番号とともに一覧表示されます。一覧には最初の20件のエラーが表示され、それより多い場合は下の注記に合計数が示されます。

**キャンセル**で実行を止めます。まだアプリから送り出されていないメッセージは送信されず、その数がパネルに表示されます。アプリは、すでに送信したメッセージについて、ブローカーの確認を最大2秒待ちます。それでも確認されないメッセージは、書き込まれたかどうか不明なため、エラーとして数えられます。Producerのタブを閉じた場合も実行は止まります。

本番接続では、実行時に接続名の入力を求められ、**本番で開始**で確定します。

<a id="batch-file"></a>

## ファイルから送信する

**ファイルから**モードでは、ファイルの各行またはレコードが1件のメッセージになります。サポートされるファイルは、JSON Lines（`.jsonl`、`.ndjson`）とCSV（`.csv`）です。

1. 上のフォームで**トピック**を入力します。すべてのメッセージがこのトピックに送られます。
2. **ファイルから**を選択し、「**ファイルを選択…**」をクリックします。
3. **開始**をクリックします。

フォームのキー、値、ヘッダー、パーティションは使われず、プレースホルダーも置き換えられません。フォームのプロデューサーの設定は適用されます。

JSON Linesでは、各行が1つのJSONオブジェクトです。例：`{"key": "k1", "value": {"id": 1}, "headers": {"source": "test"}, "partition": 0}`。どのフィールドも省略できます：

- `key`と`value`：JSON文字列は、引用符なしのテキストとして送信されます。オブジェクトや数値など、その他のJSON値はJSONテキストとして送信されます。`null`またはフィールドがない場合は、キーまたは値がないことを意味します。
- `headers`：文字列の値を持つオブジェクト。
- `partition`：パーティション番号。指定しない場合、パーティションはキーによって選ばれます。

空の行はスキップされます。ファイルはUTF-8である必要があります。

CSVでは、最初の行に列名を書きます。`value`列は必須です。`key`、`partition`、`header.NAME`の列は省略できます。例：`header.source`。`key`のセルが空の場合はキーなし、ヘッダーのセルが空の場合はそのヘッダーなしを意味します。`value`のセルが空の場合は、`null`ではなく空の値が送信されるため、CSVからtombstoneを送信することはできません。

ファイルはストリームとして読み込まれるため、合計数は事前にわからず、`—`と表示されます。16 MBを超える行やレコード、無効なJSON、負のパーティション番号は、その行のエラーとして数えられ、実行は次の行に進みます。エラーは行番号とともに表示されます。

<a id="batch-rate"></a>

## 送信レート

**レート**は、一括送信を1秒あたりの指定したメッセージ数に制限します。1以上の整数を入力します。フィールドが空の場合は**無制限**です。

メッセージは時間的に均等に分散されます。毎秒10件の場合、約100 msごとに1件が送り出されます。共有クラスターに過大な負荷をかけないため、または一定の負荷を再現するために制限を使います。

制限がない場合、アプリはブローカーが受け付ける限りの速さで送信します。レートは両方の一括送信モードに適用されます。

<a id="producer-settings"></a>

## プロデューサーの設定

**プロデューサーの設定**は、1件ずつの送信と一括送信の両方に適用されます。設定はテンプレートと履歴に保存されます。

`acks`は、書き込みを確認する必要があるレプリカの数を指定します：

- `all`：デフォルト。リーダーは、すべての同期レプリカを待ちます。最も安全な選択です。同期しているレプリカがトピックの設定`min.insync.replicas`の要求より少ない場合、書き込みは失敗します。
- `1`：リーダーだけが確認します。より高速ですが、フォロワーがコピーする前にリーダーに障害が起きると、メッセージが失われることがあります。
- `0`：プロデューサーは確認を待ちません。メッセージが失われることがあり、オフセットは返されません。

**圧縮**は、メッセージのバッチを圧縮します：`none`（デフォルト）、`gzip`、`snappy`、`lz4`、`zstd`。圧縮すると、多少のCPUと引き換えにネットワークの通信量とディスク容量を節約できます。`zstd`と`lz4`がよく使われます。小さなメッセージを1件送信する場合、効果はわずかです。

**冪等性**は`enable.idempotence`を設定します。ネットワークエラーのあとにクライアントが送信を再試行したときの重複を防ぎます。`acks`を`all`にする必要があり、それ以外の値ではエラーが表示され、何も送信されません。
