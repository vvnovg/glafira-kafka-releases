# 接続

接続とは、1つのKafkaクラスターについて保存したプロファイルで、アドレス、セキュリティ設定、パスワードを含みます。接続は左側の**接続**パネルに一覧表示されます。フォルダーで整理したり、エクスポートとインポートで別のコンピューターに移したりできます。

<a id="create"></a>

## 接続を作成する

1. **接続**パネルのヘッダーにある`+`（**新しい接続**）をクリックします。フォルダーの中に直接作成するには、フォルダーのメニューを開いて**ここに新しい接続**を選びます。
2. **名前**を入力します。名前はパネルとタブのタイトルに表示されます。
3. **ブートストラップサーバー**に、`host:port`形式のアドレスを1つ以上、コンマ区切りで入力します。例：`kafka1:9092,kafka2:9092`。到達できるブローカーが1つあれば十分で、ほかのブローカーはクライアントが自動的に見つけます。
4. **プロトコル**を選び、追加されたフィールドに入力します。[セキュリティプロトコル](connections.md#security)を参照してください。
5. 必要に応じて、**フォルダー**、**環境**、名前の横に表示される点の**色**を選びます。
6. **接続をテスト**をクリックし、**保存**をクリックします。

保存するとフォームが閉じ、クラスターの概要が開きます。

ほかに、特殊な場合のためのフィールドが2つあります。「**リクエストのタイムアウト（ms）**」では、ブローカーの応答を待つ時間を指定します。デフォルトは`30000` ms、最小値は`1000`です。低速なネットワークやVPNでは値を大きくしてください。**librdkafkaの追加プロパティ**には、任意のlibrdkafka設定を`key=value`形式で1行に1つずつ入力します。`#`で始まる行は無視されます。パスワードと鍵はここには入力できません。名前に`password`または`secret`を含むプロパティ、`sasl.jaas.config`、`ssl.key.pem`、`ssl.keystore.key`は保存時に拒否されます。

あとで接続を変更するには、名前の横の`✎`（**接続を編集**）をクリックします。削除するには、フォームを開いて**削除**をクリックし、**削除する**で確定します。

<a id="test"></a>

## 接続をテストする

**接続をテスト**は、フォームの設定を段階的に確認し、最初に失敗した段階で止まります：

1. **設定**：アドレス、証明書ファイル、パスワード、SASLのユーザー名。
2. **DNS / TCP**：ホスト名が解決でき、少なくとも1つのブートストラップサーバーへのTCP接続が開くこと。
3. **Kafka（TLS、SASL、メタデータ）**：TLSハンドシェイクとSASLログインが成功し、ブローカーがメタデータを返すこと。成功すると、ブローカー数とトピック数が表示されます。

テストには、入力済みで未保存のパスワードも含め、現在フォームにある値が使われます。何も保存されず、クラスターも変更されません。段階が失敗すると、その下にエラーメッセージと詳細が表示されます。よくあるエラーは[接続できない](troubleshooting.md#cannot-connect)で説明しています。

<a id="security"></a>

## セキュリティプロトコル

**プロトコル**は、接続先のブローカーのリスナーと一致している必要があります。どれを使うかはKafkaの管理者に確認してください。

- `PLAINTEXT`：暗号化もログインもありません。ローカルやテスト用のクラスターでよく使われます。
- `SSL`：通信がTLSで暗号化されます。クライアント証明書を使う場合はmTLSになります。
- `SASL_PLAINTEXT`：ユーザー名とパスワードでログインします。暗号化はありません。
- `SASL_SSL`：TLS上でユーザー名とパスワードでログインします。

プロトコルを変更すると、フォームにはそのプロトコルに必要なフィールドだけが表示されます。

<a id="sasl"></a>

## SASL

`SASL_PLAINTEXT`と`SASL_SSL`では、3つのフィールドに入力します：

- **SASLメカニズム**：`PLAIN`、`SCRAM-SHA-256`、`SCRAM-SHA-512`のいずれか。どれが使えるかはクラスターによって決まります。
- **ユーザー名**。
- **パスワード**。プロファイルではなく、システムの資格情報ストアに保存されます。[パスワード](connections.md#passwords)を参照してください。

SCRAMはパスワードそのものを送信しません。`PLAIN`はパスワードをそのまま送信するため、`SASL_PLAINTEXT`ではパスワードが平文で流れます。お使いのコンピューターの外にあるクラスターには、できるだけ`SASL_SSL`を使ってください。

<a id="tls"></a>

## SSLと信頼されたCA

`SSL`と`SASL_SSL`では、フォームにTLSの設定が追加されます。

**信頼されたCA証明書**は、ブローカーの証明書に署名した認証局（CA）の証明書です。オペレーティングシステムがすでにこのCAを信頼している場合は空のままにします。その場合はシステムのルート証明書が使われます。それ以外の場合は、ファイルのフルパスを入力するか、「**参照…**」をクリックします。ファイルを選ぶと、**CAの形式**フィールドが表示されます。PKCS#12とJKSでは、**トラストストアのパスワード**フィールドも表示されます。

**ホスト名を検証**はデフォルトでオンです。ブローカーの証明書が接続先のホスト名に対して発行されたものかどうかを確認します。オフにするのはテスト環境だけにしてください。たとえば、ブローカーが別の名前の自己署名証明書を使っている場合です。

<a id="mtls"></a>

## クライアント証明書（mTLS）

ブローカーが証明書でクライアントを認証する場合は、「**クライアント証明書（mTLS）**」をオンにします。証明書と鍵はKafkaの管理者が発行します。次に以下を入力します：

- **クライアント証明書**：証明書ファイルのパス。
- **クライアント証明書の形式**：PEM、PKCS#12、JKSのいずれか。
- PEMの場合：秘密鍵ファイルのパスを**クライアント秘密鍵**に。鍵が暗号化されている場合は「**鍵のパスワード（暗号化されている場合）**」も入力します。
- PKCS#12の場合：**キーストアのパスワード**。
- JKSの場合：**キーストアのパスワード**。鍵に独自のパスワードがある場合は「**鍵のパスワード（異なる場合）**」、ストアに複数の鍵がある場合は**鍵のエイリアス**も入力します。

パスは絶対パスで指定します。ファイルは接続のたびに読み込まれるため、証明書を更新したあとは再接続するだけで済みます。アプリは、鍵が証明書と一致していること、証明書の有効期限が切れていないことを確認します。

よくあるのは、Kubernetes上のクラスターで、クライアントのシークレットに`tls.crt`、`tls.key`、`ca.crt`が入っている場合です。これらをファイルに保存し、プロトコル`SSL`を選び、**信頼されたCA証明書**に`ca.crt`を指定し、`tls.crt`と`tls.key`をPEM形式のクライアント証明書と鍵として、パスワードは空のまま使います。

<a id="certificate-formats"></a>

## 証明書の形式

Glafiraは3つの形式を読み込めます。形式はファイルの拡張子から自動的に選ばれます。形式のフィールドで確認し、必要なら変更してください。

- PEM：`-----BEGIN`で始まるテキストファイル。拡張子は`.pem`、`.crt`、`.cer`、`.key`。クライアント証明書の場合、鍵は別ファイルです。信頼されたCAにはバイナリのDER証明書も使えます。
- PKCS#12：証明書と鍵を含むバイナリのストア。拡張子は`.p12`、`.pfx`。
- JKS：Javaのキーストア。拡張子は`.jks`、`.keystore`、`.truststore`。

次の2種類のファイルは、先に変換が必要です：

- JCEKSストアはサポートされていません。PKCS#12に変換してください：

```bash
keytool -importkeystore -srcstoretype JCEKS -srckeystore client.jceks -deststoretype PKCS12 -destkeystore client.p12
```

- 古いアルゴリズム（RC2、3DES）で暗号化されたPKCS#12ストアは開けないことがあります。アプリが古いアルゴリズムを報告した場合は、AESでファイルを作り直してください：

```bash
openssl pkcs12 -export -keypbe AES-256-CBC -certpbe AES-256-CBC -in tls.crt -inkey tls.key -out client.p12
```

<a id="passwords"></a>

## パスワード

SASLのパスワード、鍵とストアのパスワードは、システムの資格情報ストアに保存されます。macOSではキーチェーン、Windowsでは資格情報マネージャー、LinuxではSecret Serviceです。接続のプロファイル、エクスポートファイル、診断アーカイブには書き込まれません。

保存済みの接続を編集すると、パスワードのフィールドは空で、**変更しない場合は空のままにします**と表示されます。保存済みのパスワードを使い続けるにはフィールドを空のままにし、置き換えるには新しいパスワードを入力します。保存済みの証明書のパスワードを削除するには、フィールドの横の**保存したパスワードを削除**を選びます。保存時には、接続で使われなくなったパスワードが削除されます。たとえば、プロトコルを`PLAINTEXT`に切り替えた場合です。

アプリが資格情報ストアにアクセスできない場合は、保存時にエラーが表示されます。Linuxでは、GNOME Keyring、KWallet、またはほかのSecret Serviceプロバイダーがセッションで動作していることを確認してください。

<a id="environments"></a>

## 環境と本番

**環境**は接続に付けるラベルで、`local`、`dev`、`test`、`stage`、`prod`のいずれかです。環境はパネルの名前の横に色付きのバッジで表示されるため、どのクラスターで作業しているかが常にわかります。

`prod`を選ぶと保護が加わります。本番接続でトピックの作成、メッセージの送信、オフセットのリセット、コンシューマーセッションの開始などの変更を行うときは、接続名の入力を求められます。削除とパージでは、どの接続でも対象の名前の入力を求められ（複数のトピックを削除する場合はその数）、本番接続では両方を入力します。これらの確認はアプリのウィンドウ内に表示されます。

新しい本番接続は**読み取り専用**の状態で作成されます。変更が必要な場合はチェックを外してください。

<a id="read-only"></a>

## 読み取り専用

**読み取り専用**は、クラスターを変更する操作をすべてブロックします。トピックの作成、変更、パージ、削除、メッセージの送信、オフセットのリセット、グループの削除、コンシューマーセッションの開始です。これらの操作のボタンは非表示または無効になり、アプリのコアもこうした操作を拒否します。閲覧と読み取りは引き続き利用できます。読み取り専用の接続には、パネルの名前の横に鍵のアイコンが表示されます。

データを見るだけでよい場合、特に共有クラスターでは、このモードを使ってください。読み取り専用はアプリ内の保護であり、Kafkaのアクセス権（ACL）の代わりにはなりません。

<a id="folders"></a>

## フォルダー

フォルダーを使うと、プロジェクトや環境ごとなどに接続を整理できます。フォルダーは入れ子にできます。

- 最上位にフォルダーを作成するには、パネルのヘッダーにある`+📁`（**新しいフォルダー**）をクリックします。サブフォルダーを作成するには、フォルダーのメニューを開いて**新しいフォルダー**を選びます。名前を入力して`Enter`を押すか、`Esc`を押して取り消します。
- フォルダーのメニューを開くには、フォルダーの行の`⋯`（**その他の操作**）をクリックするか、フォルダーを右クリックします。メニューには**名前を変更**、**削除**、エクスポートとインポートのコマンドがあります。
- 削除できるのは空のフォルダーだけです。先に中の接続とサブフォルダーを移動または削除してください。
- フォルダー名は同じ階層内で一意にし、100文字以内にする必要があります。

接続を移動するには、フォルダーにドラッグするか、別の接続にドラッグしてその前に置きます。最上位に移動するには、パネルのヘッダーか一覧の下の空いた場所にドロップします。接続のフォームで**フォルダー**を選ぶこともできます。「**（ルート）**」は最上位を意味します。フォルダーも同じ方法でドラッグします。別のフォルダーの上端にドロップすると、そのフォルダーの前に置かれます。フォルダーを自身のサブフォルダーに移動することはできません。

フォルダー名をクリックすると、折りたたんだり展開したりできます。どのフォルダーを折りたたんだかはアプリが記憶します。ツリーの上の**接続を絞り込む**を使うと、名前で接続とフォルダーを検索できます。一致したフォルダーは中身ごと表示されます。

<a id="export"></a>

## エクスポート

エクスポートでは、接続とフォルダーをファイルに保存します。同僚と共有したり、別のコンピューターに移したりするときに使います。

1. すべてをエクスポートするには、パネルのヘッダーのメニュー`⋯`を開き、「**すべてエクスポート…**」を選びます。1つのフォルダーをサブフォルダーごとエクスポートするには、そのフォルダーのメニューで「**フォルダーをエクスポート…**」を選びます。
2. ファイルの保存先を選びます。提案されるファイル名は`glafira-connections-<date>.glafira-connections.json`または`<folder>.glafira-connections.json`です。

ファイルが保存されると、含まれる接続とフォルダーの数がパネルに表示されます。

ファイルには接続の設定とフォルダーの構造が含まれます。パスワードやシークレットのプロパティは含まれません。証明書ファイルも含まれず、パスだけが記録されます。ホスト、ユーザー名、パスは平文で保存されるため、それらを見てもよい人とだけファイルを共有してください。

<a id="import"></a>

## インポート

1. パネルのヘッダーのメニュー`⋯`を開き、「**インポート…**」を選びます。フォルダーに直接インポートするには、そのフォルダーのメニューで「**ここにインポート…**」を選びます。
2. `.glafira-connections.json`ファイルを選びます。**接続をインポート**ダイアログが開きます。
3. **インポート先**で、新しいフォルダーと接続の追加先を選びます。「**（ルート）**」は最上位です。
4. ファイルにある既存の接続を更新するには、**既存の接続を更新**をオンのままにします。既存の接続をそのまま残すにはオフにします。
5. プレビューを確認して**インポート**をクリックします。変更せずにダイアログを閉じるには**キャンセル**をクリックします。

プレビューはダイアログで変更するたびに更新されます。合計と、展開できる一覧が表示されます。一覧は**新規**、**更新予定**、**変更なし**、**スキップ**で、スキップされた接続にはそれぞれ理由が示されます。

アプリがファイルとお使いの接続を照合する方法：

- 接続は名前ではなく内部IDで照合されます。ファイルに同じ接続が含まれている場合、その接続は既存とみなされます。たとえば、このコンピューターからエクスポートした接続や、以前に同じ提供元からインポートした接続です。
- 更新された接続には、ファイルの設定が適用されます。パスワードとツリー内の位置は保持されます。
- 既存のフォルダーは名前の変更も移動もされません。ファイルの新しい接続は、そのフォルダーに追加されます。
- 新しい接続が同じフォルダー内の別の接続と同じ名前の場合は、番号が付きます。例：`kafka-dev (2)`。
- このバージョンのGlafiraがサポートしていない接続や、追加プロパティにシークレットを含む接続はスキップされます。

プレビューでは、証明書ファイルがこのコンピューターに見つからない場合にも警告が表示されます。パスワードはファイルに含まれないため、インポート後、パスワードが必要な接続の数がパネルに表示されます。それらの接続を1つずつ開き、パスワードを入力して保存してください。
