# メッセージの閲覧

メッセージは、トピックの**メッセージ**タブで閲覧します。閲覧ではコンシューマーグループに参加せず、何もコミットしないため、クラスターは変更されません。**読み取り専用**の接続でも使えます。グループのメンバーとして読み取るには、[コンシューマーセッション](consumer-sessions.md)を使います。

<a id="start-reading"></a>

## 読み取りを開始する

1. **トピック**の一覧からトピックを開きます。最初に**メッセージ**タブが開きます。
2. **開始**で読み取りの開始位置を選びます。[開始位置](browse.md#start-position)を参照してください。
3. 必要に応じて、形式とフィルターを設定します。
4. **読み取る**をクリックします。

メッセージは届いた順にテーブルに表示されます。ボタンの横の行には、スキャンしたメッセージ数、フィルターに一致した数、テーブルにある数が表示されます。状態も表示されます：「**読み取り中…**」、「**上限に達しました**」、「**トピックの末尾に達しました**」、「**停止しました**」。

`Live tail`がオフの場合、読み取りは**読み取る**をクリックした時点のトピックの末尾で止まります。**上限**に達した場合はそれより前に止まります。上限はフィルターに一致したメッセージを数えます。1から100000まで指定でき、大きな値にすると読み取りが遅くなります。

`Live tail`をオンにすると、読み取りは末尾で止まらず、新しいメッセージが書き込まれるたびに追加されます。古いメッセージをすべて読み終えると、状態は「**新しいメッセージを待機中…**」になります。テーブルには上限までの最新のメッセージが残り、最も古いものから削除されます。

**停止**は読み取りを止め、テーブルはそのまま残します。読み取り中は、**読み取る**ボタンが**再読み取り**に変わります。このボタンは現在の設定で読み取りをやり直し、テーブルをクリアします。ブローカーへの接続が切れた場合、アプリは自動的に再接続し、そのことを状態の行に表示します。

テーブルでは、異なるパーティションのメッセージが混在します。Kafkaが順序を保証するのは1つのパーティション内だけです。`P`列はパーティションを、`Offset`列はパーティション内の位置を示します。時刻をローカル時刻ではなくUTCで表示するには、`UTC`を選択します。

<a id="start-position"></a>

## 開始位置

**開始位置**は、各パーティションのどこから読み取りを始めるかを指定します：

- **最新N件**：最新のN件のメッセージ。Nはパーティション間で均等に分けられます。たとえば100件で4つのパーティションの場合、各パーティションから最大25件を取得します。
- **先頭から**：まだ保存されている最も古いメッセージから。
- **オフセットから**：各パーティションの同じオフセットから。パーティションにそのオフセットがない場合は、パーティションの先頭または末尾から読み取ります。このモードはパーティションが1つの場合に最も役立ちます。
- **時刻から**：指定したローカル時刻以降のタイムスタンプを持つ最初のメッセージから。それより新しいメッセージがないパーティションでは、末尾から読み取ります。
- **直近X分**：同様に、現在から遡って数えます。

**パーティション：すべて**と表示されたフィールドでは、読み取るパーティションを限定できます。パーティション番号をコンマ区切りで入力します。例：`0,2`。すべてのパーティションを読み取るには空のままにします。

<a id="filters"></a>

## フィルター

フィルターを使うと、一致したメッセージだけが表示されます。アプリは開始位置からすべてのメッセージを読み取り、1件ずつ確認するため、フィルターで読み取りが速くなることはありません。入力したフィールドすべてに一致する必要があります。

- **キーに含む**と**値に含む**：キーまたは値に含まれるテキスト。
- `regex`：これらのフィールドとヘッダーの値を正規表現として扱います。
- `Aa`：大文字と小文字を区別します。デフォルトでは区別しません。
- **ヘッダー**：メッセージにこの名前と完全に一致するヘッダーがあること。**ヘッダーの値**を入力すると、その値も確認します。
- `JSONPath`：JSONの値に対する条件。例：`$.order.status == "FAILED"`。`==`や`!=`がない場合は、パスが存在するだけで一致します。例：`$.error`。値が有効なJSONでないメッセージは一致しません。
- **開始時刻**と**終了時刻**：メッセージのタイムスタンプがこの範囲（ローカル時刻）にあること。両端を含みます。

フィルターは、デコード後にテーブルに表示されるテキストを確認します。値の形式が`hex`の場合、値のフィルターは16進数のテキストを検索します。フィルターは**読み取る**をクリックしたときに適用されます。変更したら、もう一度読み取ってください。

フィルターは開始位置を変えません。たとえば、**最新N件**とフィルターを組み合わせると、最新のN件の中からだけ一致するものを探します。トピック全体を検索するには、**先頭から**を選んで開始します。

<a id="formats"></a>

## 形式

**形式**は、キーと値のデコード方法を指定します。**キー**と**値**で別々に設定できます。変わるのは表示だけで、データは変わりません。

- `auto`：デフォルト。有効なJSONオブジェクトと配列はJSONとして、その他のUTF-8テキストは文字列として、バイナリデータは16進数として表示されます。
- `string`：UTF-8のテキスト。有効なUTF-8でないバイトは`�`に置き換えられます。
- `json`：メッセージの詳細で、インデント付きのJSONとして表示されます。値が有効なJSONでない場合は、詳細にエラーが表示されます。
- `hex`：各バイトを2桁の16進数で表示します。
- `base64`：バイトをBase64で表示します。

詳細には、実際に使われた形式が表示されます。たとえば、`auto`がJSONを検出した場合は`json`です。ヘッダーの値はテキストとして表示され、バイナリのヘッダー値は`0x`に続く16進数で表示されます。キーや値がない場合は`null`と表示されます。

非常に大きなキーと値は、テキストの先頭約1 MBだけが表示されます。これは`hex`と`base64`にも当てはまります。その場合、メッセージの詳細に警告が表示されます。

<a id="message-details"></a>

## メッセージの詳細

行をクリックすると、テーブルの横にメッセージの詳細が開きます。上部にはパーティション、オフセット、時刻が表示されます。その下には：

- **値**と**キー**：全文と、形式およびバイト単位のサイズ。JSONはインデント付きで表示されます。**コピー**でテキストをコピーできます。
- **ヘッダー**：ヘッダー名と値のテーブル。

テーブルの列は、`P`、`Offset`、**時刻**、**キー**、**値**、**ヘッダー**（ヘッダーの数）、**サイズ**（キーと値のバイト単位のサイズ）です。時刻はメッセージのタイムスタンプです。トピックの設定`message.timestamp.type`に応じて、プロデューサーまたはブローカーが設定します。

<a id="export-messages"></a>

## メッセージをコピーする

Glafiraは閲覧したメッセージをファイルに保存しません。メッセージをアプリの外に取り出すには、コピーします：

- **すべてJSONとしてコピー**は、メッセージ全体をJSONとしてコピーします。トピック、パーティション、オフセット、タイムスタンプ、キー、値、ヘッダー、サイズが含まれます。キーと値はデコードされた状態で、その形式とともに含まれます。
- **値**または**キー**の横の**コピー**は、そのテキストだけをコピーします。

コピーされるテキストには、読み取り時に選んだ形式が使われます。バイナリデータを正確にコピーするには、`hex`または`base64`で読み取ってください。非常に大きなキーと値は、`hex`と`base64`でも、表示されている部分だけがコピーされます。[形式](browse.md#formats)を参照してください。

<a id="open-in-producer"></a>

## Producerで開く

**再送信**は、同じ接続の**Producer**でメッセージを開きます。フォームには、メッセージのトピック、キー、値、ヘッダー、形式が入力されます。パーティションはKafkaに任されます。メッセージのテキスト内のプレースホルダーは置き換えられず、読み取ったとおりのコピーが送信されます。

すぐには何も送信されません。フォームを確認し、必要なら変更して、Producerから送信してください。[Producer](producer.md)を参照してください。

ボタンは次の2つの場合に無効になり、理由が表示されます：

- キーまたは値が大きすぎて、一部しか表示されていない場合。
- テキストが有効なUTF-8でないため、デコード時に情報が失われた場合。正確なコピーを送信するには、`hex`または`base64`で読み取ってください。

**読み取り専用**の接続では、このボタンは表示されません。

<a id="reset-group-here"></a>

## グループをメッセージの位置にリセットする

「**ここでグループをリセット…**」は、コンシューマーグループがこのメッセージから読み取りを始めるように、オフセットのリセットを準備します。

1. メッセージの詳細で「**ここでグループをリセット…**」をクリックします。
2. 一覧からグループを選びます。一覧には既存のグループだけが表示されます。
3. **リセットへ進む**をクリックします。

グループのタブが開き、リセットのフォームに値が入力されています。**方法**は**オフセットを指定**で、メッセージのオフセットが指定されます。**対象**は**パーティション**で、メッセージのトピックとパーティションが指定されます。この時点ではまだ何も変更されません。**プレビュー**をクリックして新しいオフセットを確認し、そこでリセットを適用します。グループにアクティブなメンバーがいない必要があります。[コンシューマーグループ](groups.md)を参照してください。

**読み取り専用**の接続では、このボタンは表示されません。
