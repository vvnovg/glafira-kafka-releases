# 消费者会话

消费者会话以消费者组真正成员的身份读取主题。

<a id="what-is"></a>

## 什么是会话

[浏览](browse.md)读取消息时不加入组，也不会改变集群中的任何内容。会话则不同：它以指定的 `group.id` 加入组，从 Kafka 获得分区，并可以提交偏移量。可用会话查看某个组将会读到的内容、通过提交移动组的偏移量，或观察组如何重平衡。

会话会影响集群。会话加入或离开时，Kafka 会重新分配该组的分区，组的其他成员会经历一次重平衡。提交会改变组的偏移量，该组的应用将使用这些偏移量。

在**只读**连接上无法使用会话，标签页会显示“**只读连接无法使用消费者会话：加入组会改变其状态。**”如果会话运行期间连接变为只读，会话会离开该组。

<a id="start-session"></a>

## 启动会话

可通过以下三种方式之一打开会话：

- **连接**面板中连接下方的**消费者会话**：空白表单；
- 主题标签页中的**以组身份读取**：已填入主题；
- 组标签页中的**以成员身份读取**：已填入该组及其有提交的主题。

每次都会打开一个新标签页，因此可以同时运行多个会话。

在**组和主题**中：

- `group.id`：要加入的组。如果不填写，应用会建议一个新名称，例如 `glafira-kafka-anna-1a2b3c`。新组没有任何提交。
- **主题**：用逗号或空格分隔的主题名称。也可以选中**按正则表达式匹配主题**，并输入**主题正则表达式**，例如 `orders\..*`。表达式从名称开头开始匹配：如果缺少 `^`，会自动添加。之后创建的匹配主题会在几分钟内（元数据刷新时）加入，这会引发一次重平衡。
- `auto.offset.reset`：对于该组没有已提交偏移量的分区，从哪里开始读取：**从末尾开始（latest）**（默认）或**从头开始（earliest）**。对于该组有已提交偏移量的分区，会从该偏移量继续读取。
- **自动提交**：自动提交已读取的偏移量。默认关闭。参见[提交](consumer-sessions.md#commits)。
- `isolation.level`：`read_committed`（默认）只显示已提交事务中的消息。`read_uncommitted` 还会显示未完成和已中止事务中的消息。

在**格式**中，选择**键格式**和**值格式**，与浏览时相同。参见[格式](browse.md#formats)。通过**缓冲区（消息数）**，可设置表格保留的消息数，范围为 1 到 100000，默认为 5000。

筛选条件的用法与浏览时相同。参见[筛选条件](browse.md#filters)。

点击**加入组**。在生产环境连接上，应用会要求输入连接名称，并点击**确认**确认。会话运行期间，表单无法更改。

<a id="reading"></a>

## 读取

按钮旁的状态行先显示**正在连接…**，然后显示**已在组中**。状态行还会显示已读取的消息数、与筛选条件匹配的消息数以及表格中的消息数。如果与 Broker 的连接断开，会话会自动重新连接，并在状态行中显示。

消息到达后会陆续出现在表格中，会话会持续读取新消息，直到你将其停止。表格已满时，最旧的消息会被移除。与浏览时一样，点击某一行可查看消息详情。参见[消息详情](browse.md#message-details)。选中 `UTC` 可按 UTC 显示时间。

会话只读取 Kafka 分配给它的分区。如果该组还有其他成员，它们会读取其他分区。如果组的成员多于分区，会话可能完全分不到分区。

**断开连接**会离开该组，其他成员将获得它的分区。关闭会话标签页也会离开该组。会话结束后，状态行显示**已断开**。

如果主题不存在，会话会因错误而停止，并显示需要检查的名称。

<a id="commits"></a>

## 提交

提交会为组保存一个偏移量。下一个读取该分区的成员，或重启后的同一个应用，会从该偏移量开始。

开启**自动提交**时，会话每隔几秒在后台提交已读取的偏移量，并在离开组时再提交一次。被筛选条件隐藏的消息也计为已读。

不开启自动提交时，会话不会自行提交任何内容。请使用以下按钮：

- **提交到所选消息**：提交所选消息之后的偏移量，仅限该消息所在的分区。该组将从下一条消息继续。如果所选消息早于当前提交，偏移量会往回移动。
- **提交所有已读消息**：提交每个已分配分区中的当前位置，包括被筛选条件隐藏的消息以及已从表格中移除的消息。

提交后，会有一行以 `topic:partition → offset` 的形式显示已提交的偏移量。在生产环境连接上，每次提交都会要求输入连接名称。

如果会话未及时响应，应用会警告无法确定提交是否生效。请在组标签页中检查偏移量。参见[组详情](groups.md#group-details)。

<a id="pause-partitions"></a>

## 暂停分区

表格右侧的面板以 `topic:partition` 的形式列出分配给会话的分区。点击分区旁的**暂停**可停止读取该分区，点击**恢复**可继续读取。已暂停的分区会标记为**已暂停**。

暂停不会离开组，因此不会引发重平衡。该分区仍分配给会话，暂停期间其他成员也不会读取它。暂停不会改变集群中的任何内容，也无需确认。

重平衡后，新分配的分区处于未暂停状态。会话离开组时，所有暂停都会结束。

<a id="rebalance-log"></a>

## 重平衡日志

分区列表下方的**重平衡日志**会记录分配的每次变化，最新的在前。每条记录包含时间以及以下三种类型之一：分配给会话的分区、从会话撤销的分区，或带有错误文本的重平衡错误。

当有成员加入或离开组、订阅的主题发生变化，或某个成员未能及时响应时，就会发生重平衡。要观察重平衡，请在另一个标签页中以相同的 `group.id` 启动第二个会话：分区会在两个会话之间划分，两个日志中都会显示这一过程。

日志保留最近 200 条记录。在第一次重平衡之前，日志显示“**尚无重平衡。**”

<a id="limits"></a>

## 限制

- 在**只读**连接上无法使用会话。
- 会话无法从选定的偏移量开始。要设置起点，请先重置组的偏移量：参见[重置偏移量](groups.md#reset-offsets)。重置要求组中没有成员，因此重置前请断开该组的会话。
- 表格最多保留 100000 条消息。较旧的消息会被移除，但仍计为已读。
- 与浏览时一样，非常大的键和值只显示一部分。
- 除非确有此意，否则不要加入正在运行的应用所在的组。会话会从应用那里夺走分区，在会话持有这些分区期间，应用不会处理它们。会话的提交（包括自动提交）会移动应用的偏移量。
