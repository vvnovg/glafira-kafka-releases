# LLM 어시스턴트(MCP)

Glafira는 LLM 어시스턴트의 게이트웨이 역할을 할 수 있습니다. 대상은 Claude Desktop, Claude Code, Cursor 또는 MCP(Model Context Protocol)를 지원하는 다른 클라이언트입니다. 어시스턴트는 열어 준 클러스터의 메타데이터를 읽고 문제를 찾도록 돕습니다. 예를 들어 복제 부족 파티션, 랙, 계속되는 리밸런싱, 부적절한 설정이 있습니다. Glafira를 통해서는 클러스터에서 아무것도 변경할 수 없습니다. 변경은 직접 인터페이스에서 합니다.

<a id="how-it-works"></a>

## 작동 방식

클라이언트는 `glafira-kafka mcp`를 실행합니다. 이것은 앱과 같은 실행 파일을 창이 없는 모드로 실행하는 것입니다. 이 명령은 로컬 소켓(Windows에서는 명명된 파이프)을 통해 실행 중인 Glafira에 연결하고, Glafira는 자체 연결로 어시스턴트의 요청에 응답합니다. 비밀번호와 인증서는 Glafira 안에 남아 있으며 어시스턴트는 이를 받지 않습니다.

Glafira가 실행 중이 아니면 클라이언트가 직접 실행하고 최대 30초 동안 기다립니다.

<a id="enable"></a>

## 사용 설정

1. **설정**을 열고 **LLM 어시스턴트(MCP)** 섹션으로 이동합니다.
2. **MCP 서버 허용**을 선택합니다. 상태에 **서버가 실행 중입니다**라고 표시됩니다.
3. 연결 양식에서 **LLM 접근(메타데이터만)** 확인란을 선택하고 저장합니다. 이 확인란을 선택하지 않은 연결은 어시스턴트에게 보이지 않습니다. 연결 목록에서 열려 있는 연결에는 `LLM` 표시가 붙습니다.

관리자가 MCP를 사용하지 못하게 했다면 확인란을 사용할 수 없으며 옆에 **조직에서 MCP를 비활성화했습니다**라고 표시됩니다.

접근 확인란은 연결을 내보내고 가져올 때 옮겨지지 않습니다. 다른 컴퓨터에서는 다시 선택하세요.

<a id="connect-client"></a>

## 클라이언트 연결

**클라이언트 연결**에는 바로 사용할 수 있는 스니펫과 **복사** 버튼이 있습니다:

- **Claude Desktop: claude\_desktop\_config.json에 추가** — 스니펫을 Claude Desktop 구성 파일의 `mcpServers` 섹션에 붙여 넣고 Claude Desktop을 다시 시작하세요.
- **Claude Code: 터미널에서 실행** — `claude mcp add` 명령입니다.
- **기타 stdio 클라이언트: 명령과 인수** — 명령으로 MCP 서버를 시작하는 모든 클라이언트용입니다(stdio).

스니펫에는 설치된 앱의 경로가 들어 있습니다. Glafira를 다른 위치에 다시 설치했다면 스니펫을 다시 복사하세요.

<a id="approve"></a>

## 클라이언트 승인

클라이언트가 처음 연결되면 Glafira가 클라이언트 이름이 표시된 대화 상자를 엽니다. **허용** 또는 **거부**를 클릭합니다. 답하기 전까지 어시스턴트는 클라이언트가 아직 승인되지 않았다는 메시지를 받고, Glafira 창에서 답해 달라고 요청합니다.

허용된 클라이언트는 이름으로 기억되며 **승인된 클라이언트** 목록에 표시됩니다. 거부는 기억되지 않습니다. 다음에 연결하면 Glafira가 다시 묻습니다. 클라이언트가 이름을 보내지 않으면 허용은 해당 세션이 끝날 때까지만 유효합니다.

<a id="what-llm-sees"></a>

## 어시스턴트가 볼 수 있는 것

어시스턴트가 볼 수 있는 항목은 다음과 같습니다:

- **LLM 접근(메타데이터만)** 확인란을 선택한 연결: 이름, 환경, 폴더.
- 호스트와 포트가 있는 브로커, 컨트롤러.
- 토픽, 파티션, 복제본, ISR, 오프셋, 메시지의 대략적인 개수.
- 브로커와 토픽의 구성. 비밀번호와 그 밖의 비밀 값은 숨겨집니다.
- 컨슈머 그룹: 상태, 프로토콜, 코디네이터, client id·호스트·`group.instance.id`가 있는 멤버, 할당, 커밋된 오프셋, 랙.

어시스턴트는 토픽의 메시지, 연결의 부트스트랩 서버와 보안 설정, 비밀번호, 인증서, librdkafka 추가 속성, 전송 기록과 템플릿을 볼 수 없습니다.

리밸런싱이 계속되는 원인을 조사하기 위해 어시스턴트는 그룹을 최대 50초 동안 관찰할 수 있습니다. 누가 나가고 들어오는지, 얼마나 자주인지, 어느 호스트인지 확인합니다. 컨슈머 자체의 구성과 로그는 Glafira를 통해 가져올 수 없으므로 어시스턴트가 사용자에게 요청합니다.

토픽, 그룹, client id의 이름은 클러스터에 접근할 수 있는 누구나 정할 수 있습니다. Glafira는 이 데이터가 어시스턴트에 대한 지시가 아니라고 어시스턴트에게 알려 줍니다.

<a id="sessions-log"></a>

## 세션, 승인 취소, 로그

클라이언트가 연결되어 있는 동안 왼쪽 패널 아래쪽에 클라이언트 이름이 있는 `LLM` 표시기가 나타나며, 요청 중에는 켜집니다. 이 표시기를 클릭하면 MCP 섹션이 열립니다.

- **실행 중인 세션**: **연결 해제**는 세션 하나를, **모두 연결 해제**는 모든 세션을 닫습니다.
- **승인된 클라이언트**: **승인 취소**는 클라이언트의 세션을 닫으며, 클라이언트는 다음에 연결할 때 다시 승인을 요청합니다.
- **LLM 접근(메타데이터만)** 확인란의 선택을 해제하면 바로 적용되며 다시 연결할 필요가 없습니다.
- **MCP 로그** — 모든 요청: 시간, 클라이언트, 도구, 연결, 결과. 응답 내용은 기록되지 않습니다. **파일 표시**를 클릭하면 `mcp-audit.jsonl` 파일이 열립니다.

MCP를 완전히 끄려면 **MCP 서버 허용** 확인란의 선택을 해제하세요. 클라이언트의 연결이 끊어집니다.

<a id="health"></a>

## 클러스터 점검과 메모

어시스턴트는 Glafira 기본 제공 클러스터 점검(`health_check` 도구)을 실행하고 그 발견 사항을 근거로 삼을 수 있습니다. 개체에 대한 메모도 남길 수 있습니다. 메모는 **발견 사항** 탭과 토픽·그룹 화면에 표시되며 클러스터는 바뀌지 않습니다. [클러스터 점검과 메모](health-check.md#with-llm)를 참고하세요.

<a id="troubleshooting"></a>

## 작동하지 않을 때

클라이언트에 Glafira의 메시지가 표시됩니다:

- `MCP is disabled in Glafira` — **MCP 서버 허용** 확인란을 선택하고 클라이언트에서 MCP 서버를 다시 시작하세요.
- `MCP is disabled by your organization` — 조직 정책으로 MCP가 비활성화되어 있습니다.
- `Glafira did not start the MCP server within 30 s` — Glafira를 직접 실행하고 **LLM 어시스턴트(MCP)** 섹션에서 상태를 확인하세요.
- `Invalid MCP token` — 클라이언트에서 MCP 서버를 다시 시작하세요. Glafira는 실행할 때마다 새 토큰을 발급합니다.

macOS에서는 서명되지 않은 Beta 빌드를 한 번 일반적인 방법으로 여세요. 그렇지 않으면 시스템이 클라이언트의 실행을 허용하지 않을 수 있습니다. [macOS에 설치](getting-started.md#install-macos)를 참고하세요.
