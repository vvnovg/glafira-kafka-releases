# 연결

연결은 Kafka 클러스터 하나에 대해 저장된 프로필로, 주소, 보안 설정, 비밀번호가 포함됩니다. 연결은 왼쪽의 **연결** 패널에 표시됩니다. 연결을 폴더로 정리할 수 있고, 내보내기와 가져오기로 다른 컴퓨터에 옮길 수 있습니다.

<a id="create"></a>

## 연결 만들기

1. **연결** 패널 헤더에서 `+` 버튼(**새 연결**)을 클릭합니다. 폴더 안에 바로 연결을 만들려면 폴더 메뉴를 열고 **여기에 새 연결**을 선택합니다.
2. **이름**을 입력합니다. 이름은 패널과 탭 제목에 표시됩니다.
3. **부트스트랩 서버** 필드에 `host:port` 형식의 주소를 하나 이상 쉼표로 구분하여 입력합니다. 예: `kafka1:9092,kafka2:9092`. 연결할 수 있는 브로커가 하나만 있어도 충분합니다. 나머지 브로커는 클라이언트가 직접 찾습니다.
4. **프로토콜**을 선택하고 프로토콜에 따라 추가되는 필드를 입력합니다. [보안 프로토콜](connections.md#security)을 참고하세요.
5. 필요하면 **폴더**, **환경**, 이름 옆 점의 **색상** 항목을 선택합니다.
6. **연결 테스트**를 클릭한 다음 **저장**을 클릭합니다.

저장하면 양식이 닫히고 클러스터 개요가 열립니다.

특수한 경우를 위한 필드가 두 개 더 있습니다. **요청 제한 시간(ms)** 값은 브로커 응답을 기다리는 시간입니다. 기본값은 `30000` ms이고 최솟값은 `1000`입니다. 느린 네트워크나 VPN에서는 값을 늘리세요. **추가 librdkafka 속성**에는 모든 librdkafka 설정을 한 줄에 하나씩 `key=value` 형식으로 입력할 수 있습니다. `#`로 시작하는 줄은 무시됩니다. 비밀번호와 키는 여기에 입력할 수 없습니다. 이름에 `password` 또는 `secret`이 포함된 속성, `sasl.jaas.config`, `ssl.key.pem`, `ssl.keystore.key`는 저장할 때 거부됩니다.

나중에 연결을 변경하려면 이름 옆의 `✎` 버튼(**연결 편집**)을 클릭하세요. 연결을 삭제하려면 양식을 열고 **삭제**를 클릭한 다음 **예, 삭제**로 확인하세요.

<a id="test"></a>

## 연결 테스트

**연결 테스트**는 양식의 설정을 단계별로 확인하고, 처음 실패한 단계에서 멈춥니다:

1. **구성** — 주소, 인증서 파일, 비밀번호, SASL 사용자 이름.
2. **DNS / TCP** — 호스트 이름이 확인되고, 하나 이상의 부트스트랩 서버에 TCP 연결이 열립니다.
3. **Kafka(TLS, SASL, 메타데이터)** — TLS 핸드셰이크와 SASL 로그인이 성공하고, 브로커가 메타데이터를 반환합니다. 성공하면 이 단계에 브로커 수와 토픽 수가 표시됩니다.

테스트에는 입력했지만 아직 저장하지 않은 비밀번호를 포함해 현재 양식에 있는 값이 사용됩니다. 아무것도 저장되지 않으며 클러스터에서도 아무것도 변경되지 않습니다. 단계가 실패하면 그 아래에 오류 내용과 세부 정보가 표시됩니다. 자주 발생하는 오류는 [연결할 수 없음](troubleshooting.md#cannot-connect)에서 설명합니다.

<a id="security"></a>

## 보안 프로토콜

**프로토콜**은 연결하려는 브로커 리스너와 일치해야 합니다. 어떤 프로토콜을 사용해야 하는지는 Kafka 관리자가 알고 있습니다.

- `PLAINTEXT` — 암호화와 로그인이 없습니다. 로컬 및 테스트 클러스터에서 흔히 사용합니다.
- `SSL` — 트래픽이 TLS로 암호화됩니다. 클라이언트 인증서를 함께 사용하면 mTLS입니다.
- `SASL_PLAINTEXT` — 암호화 없이 사용자 이름과 비밀번호로 로그인합니다.
- `SASL_SSL` — TLS를 통해 사용자 이름과 비밀번호로 로그인합니다.

프로토콜을 바꾸면 양식에는 해당 프로토콜에 필요한 필드만 표시됩니다.

<a id="sasl"></a>

## SASL

`SASL_PLAINTEXT`와 `SASL_SSL`에서는 다음 세 필드를 입력합니다:

- **SASL 메커니즘** — `PLAIN`, `SCRAM-SHA-256` 또는 `SCRAM-SHA-512`. 어떤 메커니즘이 동작하는지는 클러스터가 정합니다.
- **사용자 이름**.
- **비밀번호**. 비밀번호는 프로필이 아니라 시스템 보안 저장소에 저장됩니다. [비밀번호](connections.md#passwords)를 참고하세요.

SCRAM은 비밀번호 자체를 보내지 않습니다. `PLAIN`은 비밀번호를 그대로 보내므로 `SASL_PLAINTEXT`에서는 비밀번호가 평문으로 전송됩니다. 내 컴퓨터 밖에 있는 클러스터에는 가능하면 `SASL_SSL`을 사용하세요.

<a id="tls"></a>

## SSL과 신뢰할 수 있는 CA

`SSL`과 `SASL_SSL`에서는 양식에 TLS 설정이 추가됩니다.

**신뢰할 수 있는 CA 인증서**는 브로커 인증서에 서명한 인증 기관(CA)의 인증서입니다. 운영 체제가 이미 이 CA를 신뢰한다면 비워 두세요. 이 경우 시스템 루트 인증서가 사용됩니다. 그렇지 않으면 파일의 전체 경로를 입력하거나 **찾아보기…** 버튼을 클릭하세요. 파일을 선택하면 **CA 형식** 필드가 나타납니다. PKCS#12와 JKS에는 **트러스트스토어 비밀번호** 필드도 있습니다.

**호스트 이름 확인**은 기본적으로 켜져 있습니다. 브로커 인증서가 연결하려는 호스트 이름으로 발급되었는지 확인합니다. 예를 들어 브로커가 다른 이름의 자체 서명 인증서를 사용할 때처럼 테스트 환경에서만 끄세요.

<a id="mtls"></a>

## 클라이언트 인증서(mTLS)

브로커가 인증서로 클라이언트를 인증한다면 **클라이언트 인증서(mTLS)** 옵션을 켜세요. 인증서와 키는 Kafka 관리자가 발급합니다. 그런 다음 다음 항목을 입력합니다:

- **클라이언트 인증서** — 인증서 파일 경로.
- **클라이언트 인증서 형식** — PEM, PKCS#12 또는 JKS.
- PEM: **클라이언트 개인 키** — 개인 키 파일 경로. 키가 암호화되어 있으면 **키 비밀번호(암호화된 경우)** 필드도 입력합니다.
- PKCS#12: **키스토어 비밀번호**.
- JKS: **키스토어 비밀번호**. 키에 별도의 비밀번호가 있으면 **키 비밀번호(다른 경우)** 필드, 저장소에 키가 여러 개 있으면 **키 별칭** 필드도 입력합니다.

경로는 절대 경로여야 합니다. 파일은 앱이 연결할 때마다 읽으므로, 인증서를 갱신한 후에는 다시 연결하기만 하면 됩니다. 앱은 키가 인증서와 일치하는지, 인증서가 만료되지 않았는지 확인합니다.

흔한 예로 Kubernetes 클러스터에서는 클라이언트 시크릿에 `tls.crt`, `tls.key`, `ca.crt`가 들어 있습니다. 이 파일들을 저장하고, 프로토콜 `SSL`을 선택하고, **신뢰할 수 있는 CA 인증서**에 `ca.crt`를 지정한 다음 `tls.crt`와 `tls.key`를 비밀번호 없는 PEM 클라이언트 인증서와 키로 사용하세요.

<a id="certificate-formats"></a>

## 인증서 형식

Glafira는 세 가지 형식을 읽습니다. 형식은 파일 확장자에 따라 자동으로 선택됩니다. 형식 필드에서 확인하고 필요하면 변경하세요.

- PEM — `-----BEGIN`으로 시작하는 텍스트 파일입니다. 확장자는 `.pem`, `.crt`, `.cer`, `.key`입니다. 클라이언트 인증서의 경우 키는 별도 파일입니다. 신뢰할 수 있는 CA는 바이너리 DER 인증서여도 됩니다.
- PKCS#12 — 인증서와 키가 들어 있는 바이너리 저장소입니다. 확장자는 `.p12`, `.pfx`입니다.
- JKS — Java 키스토어입니다. 확장자는 `.jks`, `.keystore`, `.truststore`입니다.

다음 두 종류의 파일은 먼저 변환해야 합니다:

- JCEKS 저장소는 지원되지 않습니다. PKCS#12로 변환하세요:

```bash
keytool -importkeystore -srcstoretype JCEKS -srckeystore client.jceks -deststoretype PKCS12 -destkeystore client.p12
```

- 레거시 알고리즘(RC2, 3DES)으로 암호화된 PKCS#12 저장소는 열리지 않을 수 있습니다. 앱이 레거시 알고리즘을 보고하면 AES로 파일을 다시 만드세요:

```bash
openssl pkcs12 -export -keypbe AES-256-CBC -certpbe AES-256-CBC -in tls.crt -inkey tls.key -out client.p12
```

<a id="passwords"></a>

## 비밀번호

SASL 비밀번호와 키 및 저장소의 비밀번호는 시스템 보안 저장소에 저장됩니다. macOS에서는 키체인, Windows에서는 자격 증명 관리자, Linux에서는 Secret Service입니다. 비밀번호는 연결 프로필, 내보내기 파일, 진단 아카이브에 절대 기록되지 않습니다.

저장된 연결을 편집할 때 비밀번호 필드는 비어 있고 **변경하지 않으려면 비워 두세요**라는 안내가 표시됩니다. 저장된 비밀번호를 유지하려면 필드를 비워 두고, 바꾸려면 새 비밀번호를 입력하세요. 저장된 인증서 비밀번호를 삭제하려면 필드 옆의 **저장된 비밀번호 제거**를 선택하세요. 저장할 때 연결에서 더 이상 사용하지 않는 비밀번호는 삭제됩니다. 예를 들어 프로토콜을 `PLAINTEXT`로 바꾼 경우입니다.

앱이 보안 저장소에 접근할 수 없으면 저장할 때 오류가 표시됩니다. Linux에서는 세션에서 GNOME Keyring, KWallet 또는 다른 Secret Service 제공자가 실행 중인지 확인하세요.

<a id="environments"></a>

## 환경과 운영 환경 연결

**환경**은 연결에 `local`, `dev`, `test`, `stage`, `prod` 중 하나를 표시합니다. 환경은 패널에서 이름 옆에 색상 배지로 표시되므로 어떤 클러스터에서 작업 중인지 항상 알 수 있습니다.

`prod`는 보호 기능을 추가합니다. 운영 환경 연결에서 토픽 만들기, 메시지 보내기, 오프셋 재설정, 컨슈머 세션 시작 같은 변경을 하려면 연결 이름을 입력해야 합니다. 삭제와 비우기는 모든 연결에서 대상의 이름을 입력해야 하고(토픽 여러 개를 삭제할 때는 개수), 운영 환경 연결에서는 둘 다 입력합니다. 이러한 확인은 앱 창 안에 표시됩니다.

새 운영 환경 연결은 **읽기 전용** 상태로 시작합니다. 변경이 필요하면 확인란을 선택 해제하세요.

<a id="read-only"></a>

## 읽기 전용

**읽기 전용** 모드는 클러스터를 변경하는 모든 작업을 차단합니다. 토픽 만들기, 변경, 비우기, 삭제, 메시지 보내기, 오프셋 재설정, 그룹 삭제, 컨슈머 세션 시작이 해당됩니다. 이러한 작업의 버튼은 숨겨지거나 비활성화되며, 앱 코어도 이런 작업을 거부합니다. 조회와 읽기는 계속 사용할 수 있습니다. 패널에서 이름 옆의 자물쇠 아이콘은 읽기 전용 연결을 나타냅니다.

데이터를 보기만 하면 될 때, 특히 공유 클러스터에서는 이 모드를 사용하세요. 읽기 전용은 앱 내부의 보호 기능이며 Kafka의 접근 권한(ACL)을 대신하지 않습니다.

<a id="folders"></a>

## 폴더

폴더를 사용하면 프로젝트별이나 환경별 등으로 연결을 정리할 수 있습니다. 폴더는 중첩할 수 있습니다.

- 최상위 수준에 폴더를 만들려면 패널 헤더에서 `+📁` 버튼(**새 폴더**)을 클릭합니다. 하위 폴더를 만들려면 폴더 메뉴를 열고 **새 폴더**를 선택합니다. 이름을 입력하고 `Enter`를 누르거나, `Esc`를 눌러 취소합니다.
- 폴더 메뉴를 열려면 폴더 행의 `⋯` 버튼(**추가 작업**)을 클릭하거나 폴더를 오른쪽 클릭합니다. 메뉴에는 **이름 바꾸기**, **삭제**, 내보내기 및 가져오기 명령이 있습니다.
- 빈 폴더만 삭제할 수 있습니다. 먼저 그 안의 연결과 하위 폴더를 옮기거나 삭제하세요.
- 폴더 이름은 같은 수준 안에서 고유해야 하며 최대 100자입니다.

연결을 옮기려면 폴더 위로 드래그하거나, 다른 연결 위로 드래그하여 그 앞에 놓습니다. 최상위 수준으로 옮기려면 패널 헤더나 목록 아래 빈 공간에 놓으세요. 연결 양식에서 **폴더**를 선택할 수도 있습니다. 목록의 **(루트)** 항목은 최상위 수준을 뜻합니다. 폴더도 같은 방법으로 드래그합니다. 폴더를 다른 폴더의 위쪽 가장자리에 놓으면 그 폴더 앞에 배치됩니다. 폴더를 자기 하위 폴더 안으로 옮길 수는 없습니다.

폴더 이름을 클릭하면 접히거나 펼쳐집니다. 앱은 어떤 폴더가 접혀 있는지 기억합니다. 트리 위의 **연결 필터** 필드를 사용하면 이름으로 연결과 폴더를 찾을 수 있습니다. 일치하는 폴더는 모든 내용과 함께 표시됩니다.

<a id="export"></a>

## 내보내기

내보내기는 연결과 폴더를 파일로 저장합니다. 예를 들어 동료와 공유하거나 다른 컴퓨터로 옮길 때 사용합니다.

1. 모두 내보내려면 패널 헤더 메뉴 `⋯`를 열고 **모두 내보내기…** 항목을 선택합니다. 폴더 하나를 하위 폴더와 함께 내보내려면 그 폴더의 메뉴에서 **폴더 내보내기…** 항목을 선택합니다.
2. 파일을 저장할 위치를 선택합니다. 제안되는 이름은 `glafira-connections-<date>.glafira-connections.json` 또는 `<folder>.glafira-connections.json`입니다.

파일이 저장되면 패널에 파일에 포함된 연결과 폴더의 수가 표시됩니다.

파일에는 연결 설정과 폴더 구조가 들어 있습니다. 비밀번호와 비밀 속성은 포함되지 않습니다. 인증서 파일도 포함되지 않으며 경로만 저장됩니다. 호스트, 사용자 이름, 경로는 일반 텍스트로 저장되므로 이를 봐도 되는 사람과만 파일을 공유하세요.

## 가져오기

1. 패널 헤더 메뉴 `⋯`를 열고 **가져오기…** 항목을 선택합니다. 폴더 안으로 바로 가져오려면 그 폴더의 메뉴에서 **여기로 가져오기…** 항목을 선택합니다.
2. `.glafira-connections.json` 파일을 선택합니다. **연결 가져오기** 대화 상자가 열립니다.
3. **가져올 위치**에서 새 폴더와 연결이 들어갈 곳을 선택합니다. **(루트)** 항목은 최상위 수준입니다.
4. 이미 있는 연결을 파일 내용으로 업데이트하려면 **기존 연결 업데이트** 옵션을 켜 둡니다. 기존 연결을 그대로 두려면 끕니다.
5. 미리 보기를 확인하고 **가져오기**를 클릭합니다. 변경 없이 대화 상자를 닫으려면 **취소**를 클릭합니다.

미리 보기는 대화 상자에서 무언가를 바꿀 때마다 업데이트됩니다. 합계와 펼칠 수 있는 목록이 표시됩니다: **새 항목**, **업데이트 예정**, **변경 없음**, **건너뜀**. 건너뛴 연결마다 그 이유가 표시됩니다.

앱이 파일과 기존 연결을 대조하는 방식은 다음과 같습니다:

- 연결은 이름이 아니라 내부 ID로 대조합니다. 파일에 같은 연결이 들어 있으면 기존 연결로 간주합니다. 예를 들어 이 컴퓨터에서 내보냈거나 이전에 같은 출처에서 가져온 경우입니다.
- 업데이트되는 연결은 파일의 설정을 받습니다. 비밀번호와 트리에서의 위치는 유지됩니다.
- 기존 폴더의 이름은 바뀌지 않고 위치도 옮겨지지 않습니다. 파일의 새 연결은 그대로 그 폴더에 들어갑니다.
- 새 연결의 이름이 같은 폴더의 다른 연결과 같으면 번호가 붙습니다. 예: `kafka-dev (2)`.
- 이 버전의 Glafira가 지원하지 않는 연결이나 추가 속성에 비밀 정보가 들어 있는 연결은 건너뜁니다.

미리 보기는 이 컴퓨터에서 인증서 파일을 찾을 수 없을 때에도 경고합니다. 비밀번호는 파일에 없으므로 가져온 후 패널에 비밀번호가 필요한 연결 수가 표시됩니다. 해당 연결을 하나씩 열어 비밀번호를 입력하고 저장하세요.
