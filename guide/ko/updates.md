# 업데이트 및 진단

이 장에서는 앱 업데이트 방법, **Glafira 정보** 화면, 진단 아카이브, 프로젝트를 후원하는 방법을 설명합니다.

<a id="updates"></a>

## 업데이트

앱은 시작할 때 새 버전이 있는지 한 번 확인합니다. 새 버전이 있으면 탭 위의 알림에 그 버전이 표시됩니다. **세부 정보**를 클릭하면 **Glafira 정보** 화면이 열립니다. 인터넷에 연결되어 있지 않은 경우처럼 확인에 실패하면 아무 메시지도 표시되지 않습니다.

직접 확인하려면:

1. 왼쪽 패널 아래쪽에서 **Glafira 정보**를 엽니다.
2. **업데이트** 섹션에서 **업데이트 확인**을 클릭합니다.
3. 새 버전이 있으면 화면에 버전 번호와 릴리스 노트가 표시됩니다. **설치 후 다시 시작**을 클릭합니다.

앱은 업데이트를 다운로드하고 서명을 확인한 다음 설치하고 다시 시작합니다. 네트워크 문제로 다운로드가 중단되면 자동으로 다시 시도하며, 시도는 모두 세 번까지입니다. 세 번 모두 실패하면 앱이 다음 오류를 표시합니다: **업데이트 다운로드가 중단되었습니다. 네트워크를 확인하고 다시 시도하세요**. 서명 확인에 실패하면 앱이 다음 오류를 표시합니다: **업데이트 서명을 확인하지 못했습니다. 업데이트가 설치되지 않았습니다**.

앱은 컴퓨터의 모든 사용자를 위해 설치되므로 설치할 때 관리자 비밀번호를 물을 수 있습니다. macOS에서는 `.pkg` 설치 프로그램, Windows에서는 `.msi` 설치 프로그램, Linux에서는 `.deb` 또는 `.rpm` 패키지로 설치한 경우입니다. 관리자 권한이 없는 사용자는 이런 설치를 업데이트할 수 없습니다.

메시지를 읽는 중이거나, 컨슈머 세션이 실행 중이거나, 일괄 전송이 진행 중이면 앱은 먼저 확인을 요청하고 활성 세션 수를 알려 줍니다. 세션을 중지하고 계속하려면 **세션 중지 후 업데이트**를, 그렇지 않으면 **취소**를 클릭하세요. 연결, 설정 및 기타 데이터는 업데이트 후에도 유지됩니다.

업데이트는 GitHub의 릴리스 페이지에서 다운로드됩니다. '**업데이트를 확인하지 못했습니다**' 오류로 확인에 실패하면 네트워크나 프록시를 확인하세요. '**이 빌드에는 업데이트가 구성되어 있지 않습니다**' 메시지는 이 빌드가 업데이트 키 없이 만들어졌다는 뜻입니다. 예를 들어 개발용 또는 테스트용 빌드입니다. 이 경우 릴리스 페이지에서 새 버전을 다운로드하세요: https://github.com/vvnovg/glafira-kafka-releases/releases

조직은 정책을 통해 업데이트 확인을 끄거나 내부 미러로 지정할 수 있습니다. 확인이 꺼져 있으면 **업데이트 확인**을 클릭한 후 **업데이트** 섹션에 '**업데이트는 조직에서 관리합니다**'라는 메시지가 표시됩니다. '**이 빌드에는 업데이트가 구성되어 있지 않습니다**' 메시지와 마찬가지로 이 메시지는 클릭한 후에만 나타나며, 이런 경우 시작할 때의 확인에서는 아무것도 표시되지 않습니다.

## Glafira 정보

왼쪽 패널 아래쪽에서 **Glafira 정보**를 여세요. macOS에서는 '도움말' 메뉴의 **Glafira 정보** 항목으로도 열 수 있습니다.

화면에는 앱에 대한 짧은 설명과 다음 항목이 표시됩니다:

- **버전** — 버전 번호. **Build** — 앱을 빌드한 소스 코드의 식별자. 지원 요청에는 둘 다 포함하세요.
- **시스템** — 운영 체제와 프로세서 아키텍처.
- **라이선스** — Apache 2.0. 링크를 클릭하면 브라우저에서 라이선스 본문이 열립니다.
- **조직 정책** — **설정됨** 또는 **없음**. 정책의 오류는 아래에 나열됩니다.
- **데이터:** 연결 프로필, 템플릿, 기록, 설정이 있는 폴더.
- **로그:** 로그 파일이 있는 폴더. [로그](troubleshooting.md#logs)를 참고하세요.

이 화면에는 **업데이트** 섹션과 **진단** 섹션도 있습니다.

## 진단 아카이브

진단 아카이브는 지원 담당자가 문제를 파악하는 데 필요한 정보를 모읍니다. 아카이브를 만들려면:

1. **Glafira 정보**를 엽니다.
2. **진단** 섹션에서 **진단 정보 수집**을 클릭합니다. macOS에서는 '도움말' 메뉴의 **진단 정보 수집…** 항목을 선택해도 됩니다.
3. 파일을 저장할 위치를 선택합니다. 제안되는 이름은 `diagnostics-<date>.zip`입니다.

아카이브가 저장되면 화면에 그 경로가 표시됩니다. ZIP 파일에는 다음이 들어 있습니다:

- `info.json` — 앱 버전과 빌드, 운영 체제, 데이터 및 로그 폴더 경로, 정책 상태.
- `connections.json` — 연결 프로필: 이름, 환경, 부트스트랩 서버, 프로토콜, SASL 사용자 이름, 인증서 파일 경로, 추가 속성, 제한 시간.
- `logs/` — 앱 로그 파일.

아카이브에는 비밀번호가 없습니다. 비밀번호는 시스템 보안 저장소에 보관되며, 비밀번호와 비밀 정보가 들어 있는 추가 속성은 연결을 저장할 때 거부됩니다. 인증서 파일도 포함되지 않습니다. 호스트 이름, 사용자 이름, 파일 경로는 일반 텍스트로 저장되며, 로그에는 Kafka 오류 메시지의 브로커 주소가 들어 있습니다. 회사 밖으로 보내기 전에 아카이브를 살펴보세요.

앱은 스스로 아무것도 보내지 않습니다. 지원 요청에 아카이브를 직접 첨부하세요. [지원 문의](troubleshooting.md#support)를 참고하세요.
