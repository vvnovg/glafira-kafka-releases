# Подключения

Подключение — сохранённый профиль одного кластера Kafka: адреса, настройки безопасности и пароли. Подключения перечислены в панели **Подключения** слева. Их можно раскладывать по папкам и переносить на другой компьютер экспортом и импортом.

<a id="create"></a>

## Создание подключения

1. Нажмите `+` ( **Новое подключение** ) в заголовке панели **Подключения**. Чтобы создать подключение сразу в папке, откройте меню папки и выберите **Новое подключение здесь**.
2. Заполните поле **Имя**. Имя показывается в панели и в заголовках вкладок.
3. В поле **Bootstrap-серверы** укажите один или несколько адресов `host:port` через запятую, например `kafka1:9092,kafka2:9092`. Достаточно одного доступного брокера: остальные клиент найдёт сам.
4. Выберите **Протокол** и заполните поля, которые он добавит. См. [Протоколы безопасности](connections.md#security).
5. При желании заполните поля **Папка**, **Окружение** и **Цвет** (цвет точки рядом с именем).
6. Нажмите **Проверить подключение**, затем **Сохранить**.

После сохранения форма закроется и откроется обзор кластера.

Ещё два поля — для особых случаев. **Таймаут запроса, мс** — сколько ждать ответа брокера. По умолчанию `30000` мс, минимум — `1000`. Увеличьте его для медленной сети или VPN. В поле **Доп. свойства librdkafka** можно указать любые параметры librdkafka в виде `key=value`, по одному на строку. Строки, начинающиеся с `#`, пропускаются. Пароли и ключи сюда указывать нельзя: свойства, в имени которых есть `password` или `secret`, а также `sasl.jaas.config`, `ssl.key.pem` и `ssl.keystore.key` при сохранении отклоняются.

Чтобы потом изменить подключение, нажмите `✎` ( **Изменить подключение** ) рядом с его именем. Чтобы удалить, откройте форму, нажмите **Удалить** и подтвердите кнопкой **Да, удалить**.

<a id="test"></a>

## Проверка подключения

**Проверить подключение** проверяет настройки формы по шагам и останавливается на первом неудачном:

1. **Конфигурация** — адреса, файлы сертификатов, пароли и имя пользователя SASL.
2. **DNS / TCP** — имена хостов разрешаются, и TCP-соединение хотя бы с одним bootstrap-сервером открывается.
3. **Kafka (TLS, SASL, метаданные)** — TLS-рукопожатие и вход SASL проходят, брокер возвращает метаданные. При успехе шаг показывает число брокеров и топиков.

Проверка берёт значения, которые сейчас в форме, включая введённые, но не сохранённые пароли. Ничего не сохраняется и не меняется в кластере. Если шаг не прошёл, под ним показывается текст ошибки и подробности. Частые ошибки разобраны в разделе [Не удаётся подключиться](troubleshooting.md#cannot-connect).

<a id="security"></a>

## Протоколы безопасности

**Протокол** должен совпадать с листенером брокера, к которому вы подключаетесь. Какой нужен, знают администраторы Kafka.

- `PLAINTEXT` — без шифрования и без входа. Обычно для локальных и тестовых кластеров.
- `SSL` — трафик шифруется TLS. С клиентским сертификатом это mTLS.
- `SASL_PLAINTEXT` — вход по логину и паролю, без шифрования.
- `SASL_SSL` — вход по логину и паролю поверх TLS.

При смене протокола форма показывает только нужные ему поля.

<a id="sasl"></a>

## SASL

Для `SASL_PLAINTEXT` и `SASL_SSL` заполните три поля:

- **Механизм SASL** — `PLAIN`, `SCRAM-SHA-256` или `SCRAM-SHA-512`. Какой работает, определяет кластер.
- **Пользователь**.
- **Пароль**. Он сохраняется в системном хранилище секретов, а не в профиле. См. [Пароли](connections.md#passwords).

SCRAM не передаёт сам пароль. `PLAIN` передаёт его как есть, поэтому через `SASL_PLAINTEXT` пароль идёт открытым текстом. Для кластеров за пределами вашего компьютера по возможности используйте `SASL_SSL`.

<a id="tls"></a>

## SSL и доверенный CA

Для `SSL` и `SASL_SSL` форма добавляет настройки TLS.

**Доверенный CA** — сертификат центра сертификации (CA), которым подписаны сертификаты брокеров. Оставьте поле пустым, если операционная система уже доверяет этому CA: тогда используются системные корневые сертификаты. Иначе укажите полный путь к файлу или нажмите **Выбрать…**. После выбора файла появится поле **Формат CA**. Для PKCS#12 и JKS — ещё и **Пароль хранилища CA**.

**Проверять hostname** по умолчанию включено. Приложение проверяет, что сертификат брокера выдан на то имя хоста, к которому вы подключаетесь. Отключайте проверку только в тестовых средах, например если у брокеров самоподписанные сертификаты на другие имена.

<a id="mtls"></a>

## Клиентский сертификат (mTLS)

Если брокеры проверяют клиентов по сертификату, включите **Клиентский сертификат (mTLS)**. Сертификат и ключ выдают администраторы Kafka. Затем заполните:

- **Сертификат клиента** — путь к файлу сертификата.
- **Формат клиентского сертификата** — PEM, PKCS#12 или JKS.
- Для PEM: **Ключ клиента** — путь к файлу закрытого ключа, и **Пароль ключа (если зашифрован)**, если ключ зашифрован.
- Для PKCS#12: **Пароль хранилища клиента**.
- Для JKS: **Пароль хранилища клиента**, **Пароль ключа (если отличается)**, если у ключа свой пароль, и **Alias ключа**, если ключей в хранилище несколько.

Пути должны быть абсолютными. Файлы читаются при каждом подключении, поэтому после замены сертификата достаточно переподключиться. Приложение проверяет, что ключ подходит к сертификату и срок действия сертификата не истёк.

Частый случай — кластер в Kubernetes, где в секрете клиента лежат `tls.crt`, `tls.key` и `ca.crt`. Сохраните их в файлы, выберите протокол `SSL`, в поле **Доверенный CA** укажите `ca.crt`, а `tls.crt` и `tls.key` — как сертификат и ключ клиента в формате PEM, пароли оставьте пустыми.

<a id="certificate-formats"></a>

## Форматы сертификатов

Glafira читает три формата. Формат выбирается автоматически по расширению файла; проверьте его в поле формата и при необходимости смените.

- PEM — текстовый файл, начинается с `-----BEGIN`. Расширения `.pem`, `.crt`, `.cer`, `.key`. Ключ клиентского сертификата — отдельным файлом. Доверенный CA может быть и двоичным сертификатом DER.
- PKCS#12 — двоичное хранилище с сертификатом и ключом. Расширения `.p12`, `.pfx`.
- JKS — хранилище Java. Расширения `.jks`, `.keystore`, `.truststore`.

Два вида файлов нужно сначала преобразовать:

- Хранилища JCEKS не поддерживаются. Преобразуйте их в PKCS#12:

```bash
keytool -importkeystore -srcstoretype JCEKS -srckeystore client.jceks -deststoretype PKCS12 -destkeystore client.p12
```

- Хранилища PKCS#12, зашифрованные устаревшими алгоритмами (RC2, 3DES), могут не открыться. Если приложение сообщает об устаревшем алгоритме, пересоздайте файл с AES:

```bash
openssl pkcs12 -export -keypbe AES-256-CBC -certpbe AES-256-CBC -in tls.crt -inkey tls.key -out client.p12
```

<a id="passwords"></a>

## Пароли

Пароль SASL и пароли ключей и хранилищ сохраняются в системном хранилище секретов: Keychain на macOS, Credential Manager на Windows, Secret Service на Linux. Они никогда не попадают в профиль подключения, файлы экспорта и архив диагностики.

При изменении сохранённого подключения поля паролей пусты, в них написано «**оставьте пустым, чтобы не менять**». Оставьте поле пустым, чтобы сохранить прежний пароль, или введите новый, чтобы заменить его. Чтобы удалить сохранённый пароль сертификата, отметьте **удалить сохранённый** рядом с полем. При сохранении пароли, которые подключению больше не нужны, удаляются — например, после смены протокола на `PLAINTEXT`.

Если приложение не может обратиться к хранилищу секретов, при сохранении показывается ошибка. На Linux проверьте, что в вашем сеансе запущен GNOME Keyring, KWallet или другой поставщик Secret Service.

<a id="environments"></a>

## Окружения и prod

**Окружение** помечает подключение: `local`, `dev`, `test`, `stage` или `prod`. Окружение показывается цветной меткой рядом с именем в панели — так всегда видно, с каким кластером вы работаете.

`prod` добавляет защиту. Любое изменение на prod-подключении — например, создание топика, отправка сообщения, сброс оффсетов или запуск consumer-сессии — требует ввести имя подключения. Удаление и очистка на любом подключении требуют ввести имя объекта (при удалении нескольких топиков — их число), а на prod — оба имени. Подтверждения показываются внутри окна приложения.

Новое prod-подключение создаётся с флажком **Только чтение**. Снимите его, если нужно вносить изменения.

<a id="read-only"></a>

## Только чтение

Флажок **Только чтение** запрещает всё, что меняет кластер: создание, изменение, очистку и удаление топиков, отправку сообщений, сброс оффсетов, удаление групп и запуск consumer-сессий. Кнопки этих действий скрыты или неактивны, а ядро приложения тоже отклоняет такие операции. Просмотр и чтение остаются доступны. Подключения только для чтения отмечены значком замка рядом с именем в панели.

Включайте этот режим, когда нужно только смотреть данные, особенно на общих кластерах. «Только чтение» — защита на стороне приложения: она не заменяет права доступа (ACL) в Kafka.

<a id="folders"></a>

## Папки

Папки помогают упорядочить подключения, например по проектам или окружениям. Папки могут быть вложенными.

- Чтобы создать папку верхнего уровня, нажмите `+📁` ( **Новая папка** ) в заголовке панели. Чтобы создать вложенную папку, откройте меню папки и выберите **Новая папка**. Введите имя и нажмите `Enter` или `Esc` для отмены.
- Меню папки открывается кнопкой `⋯` ( **Ещё действия** ) в строке папки или правым кликом по папке. В меню есть **Переименовать**, **Удалить** и команды экспорта и импорта.
- Удалить можно только пустую папку. Сначала перенесите или удалите её подключения и вложенные папки.
- Имена папок должны быть уникальными в пределах одного уровня и не длиннее 100 символов.

Чтобы перенести подключение, перетащите его на папку или на другое подключение — тогда оно встанет перед ним. Чтобы перенести на верхний уровень, бросьте его на заголовок панели или на пустое место под списком. Можно и выбрать папку в поле **Папка** формы подключения; **(корень)** означает верхний уровень. Папки перетаскиваются так же. Если бросить папку на верхний край другой папки, она встанет перед ней. Переместить папку в её собственную вложенную папку нельзя.

Щелчок по имени папки сворачивает или разворачивает её. Приложение запоминает, какие папки свёрнуты. Поле **Фильтр подключений** над деревом ищет подключения и папки по имени. Совпавшие папки показываются со всем содержимым.

<a id="export"></a>

## Экспорт

Экспорт сохраняет подключения и папки в файл — например, чтобы поделиться ими с коллегами или перенести на другой компьютер.

1. Чтобы экспортировать всё, откройте меню `⋯` в заголовке панели и выберите **Экспортировать всё…**. Чтобы экспортировать одну папку с вложенными, выберите в её меню **Экспортировать папку…**.
2. Выберите, куда сохранить файл. Предлагается имя `glafira-connections-<дата>.glafira-connections.json` или `<папка>.glafira-connections.json`.

Когда файл сохранён, панель показывает, сколько в нём подключений и папок.

В файле — настройки подключений и структура папок. Паролей и секретных свойств в нём нет. Файлов сертификатов тоже нет: сохраняются только пути к ним. Хосты, имена пользователей и пути хранятся открытым текстом, поэтому передавайте файл только тем, кому их можно видеть.

<a id="import"></a>

## Импорт

1. Откройте меню `⋯` в заголовке панели и выберите **Импортировать…**. Чтобы импортировать сразу в папку, выберите в её меню **Импортировать сюда…**.
2. Выберите файл `.glafira-connections.json`. Откроется диалог **Импорт подключений**.
3. В поле **Куда импортировать** выберите, куда попадут новые папки и подключения. **(корень)** — верхний уровень.
4. Оставьте флажок **Обновлять существующие подключения**, чтобы обновить уже существующие подключения из файла. Снимите его, чтобы оставить их как есть.
5. Проверьте предпросмотр и нажмите **Импортировать** или **Отмена**, чтобы закрыть диалог без изменений.

Предпросмотр обновляется после каждого изменения в диалоге. В нём — итоги и раскрываемые списки: **Новые**, **Обновятся**, **Без изменений** и **Пропущены** с причиной для каждого пропущенного подключения.

Как приложение сопоставляет файл с вашими подключениями:

- Подключения сопоставляются по внутреннему ID, а не по имени. Подключение считается существующим, если в файле то же самое подключение: например, оно было экспортировано с этого компьютера или уже импортировано раньше из того же источника.
- Обновлённое подключение получает настройки из файла. Ваши пароли и его место в дереве сохраняются.
- Существующие папки не переименовываются и не переносятся. Новые подключения из файла всё равно попадают в них.
- Если у нового подключения такое же имя, как у другого в той же папке, к имени добавляется номер, например `kafka-dev (2)`.
- Подключения, которые эта версия Glafira не поддерживает или в доп. свойствах которых есть секреты, пропускаются.

Предпросмотр также предупреждает, если файлы сертификатов не найдены на этом компьютере. Паролей в файле нет, поэтому после импорта панель сообщает, скольким подключениям они нужны. Откройте каждое из них, введите пароли и сохраните.
