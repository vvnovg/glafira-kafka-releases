# LLM-ассистенты (MCP)

Glafira может работать шлюзом для LLM-ассистента: Claude Desktop, Claude Code, Cursor или другого клиента с поддержкой MCP (Model Context Protocol). Ассистент читает метаданные кластеров, которые вы ему открыли, и помогает найти проблемы: недореплицированные партиции, лаг, постоянные ребалансы, неудачные настройки. Изменить что-либо в кластере через Glafira он не может: изменения вы делаете сами в интерфейсе.

<a id="how-it-works"></a>

## Как это устроено

Клиент запускает `glafira-kafka mcp` — тот же файл приложения в режиме без окна. Эта команда соединяется с запущенной Glafira через локальный сокет (на Windows — именованный канал), а Glafira отвечает на запросы ассистента через свои подключения. Пароли и сертификаты остаются в Glafira, ассистент их не получает.

Если Glafira не запущена, клиент запустит её сам и подождёт до 30 секунд.

<a id="enable"></a>

## Включение

1. Откройте **Настройки**, раздел **LLM-ассистенты (MCP)**.
2. Отметьте **Разрешить MCP-сервер**. Статус сменится на **Сервер работает**.
3. В форме подключения отметьте **Доступ для LLM (только метаданные)** и сохраните. Подключения без этого флажка ассистент не видит. В дереве подключений у открытых подключений есть значок `LLM`.

Если администратор запретил MCP, флажок недоступен и рядом написано **MCP отключён вашей организацией**.

Флажок доступа не переносится при экспорте и импорте подключений: на другом компьютере его нужно отметить заново.

<a id="connect-client"></a>

## Подключение клиента

В блоке **Подключение клиента** есть готовые фрагменты и кнопка **Копировать**:

- **Claude Desktop: добавьте в claude\_desktop\_config.json** — вставьте фрагмент в раздел `mcpServers` файла конфигурации Claude Desktop и перезапустите Claude Desktop;
- **Claude Code: выполните в терминале** — команда `claude mcp add`;
- **Другие stdio-клиенты: команда и аргументы** — для любого клиента, который запускает MCP-сервер командой (stdio).

Во фрагментах — путь к установленному приложению. Если вы переустановили Glafira в другое место, скопируйте фрагмент заново.

<a id="approve"></a>

## Подтверждение клиента

Когда клиент подключается впервые, Glafira показывает диалог с его именем. Нажмите **Разрешить** или **Отклонить**. Пока вы не ответили, ассистент получает сообщение, что клиент ещё не подтверждён, и попросит вас ответить в окне Glafira.

Разрешённый клиент запоминается по имени и появляется в списке **Подтверждённые клиенты**. Отказ не запоминается: при следующем подключении Glafira спросит снова. Если клиент не сообщил своё имя, разрешение действует только до конца сеанса.

<a id="what-llm-sees"></a>

## Что видит ассистент

Ассистент видит:

- подключения с флажком **Доступ для LLM (только метаданные)**: имя, окружение, папку;
- брокеры с хостами и портами, контроллер;
- топики, партиции, реплики, ISR, оффсеты, примерное число сообщений;
- конфиги брокеров и топиков, при этом значения паролей и других секретов скрыты;
- consumer groups: состояние, протокол, координатор, участников с client id, хостом и `group.instance.id`, назначения, закоммиченные оффсеты и лаг.

Ассистент не видит сообщений в топиках, строки bootstrap и настроек безопасности подключения, паролей, сертификатов, дополнительных свойств librdkafka, истории отправки и шаблонов.

Чтобы разобраться с постоянными ребалансами, ассистент может наблюдать за группой до 50 секунд: кто выходит и входит, как часто и с какого хоста. Конфиги и логи самих консьюмеров через Glafira недоступны, их ассистент попросит у вас.

Имена топиков, групп и client id может задать любой, у кого есть доступ к кластеру. Glafira предупреждает ассистента, что эти данные — не инструкции для него.

<a id="sessions-log"></a>

## Сессии, отзыв и журнал

Пока клиент подключён, внизу боковой панели показан индикатор `LLM` с именем клиента; во время запроса он подсвечивается. Щелчок по нему открывает раздел MCP.

- **Активные сессии**: **Отключить** закрывает одну сессию, **Отключить всех** — все.
- **Подтверждённые клиенты**: **Отозвать** закрывает сессии клиента, и при следующем подключении он снова попросит подтверждение.
- Снятый флажок **Доступ для LLM (только метаданные)** действует сразу, переподключаться не нужно.
- **Журнал MCP** — каждый запрос: время, клиент, инструмент, подключение, результат. Содержимое ответов не записывается. **Показать файл** открывает файл `mcp-audit.jsonl`.

Чтобы выключить MCP совсем, снимите флажок **Разрешить MCP-сервер**: клиенты отключатся.

<a id="health"></a>

## Проверка кластера и замечания

Ассистент может запустить встроенную проверку кластера Glafira (инструмент `health_check`) и опираться на её находки. Он может также оставлять замечания об объектах: они появляются на вкладке **Замечания** и на экранах топиков и групп, а кластер при этом не меняется. См. [Проверка кластера и замечания](health-check.md#with-llm).

<a id="troubleshooting"></a>

## Если не работает

Клиент показывает сообщение из Glafira:

- `MCP is disabled in Glafira` — включите **Разрешить MCP-сервер** и перезапустите MCP-сервер в клиенте;
- `MCP is disabled by your organization` — MCP запрещён политикой организации;
- `Glafira did not start the MCP server within 30 s` — запустите Glafira вручную и посмотрите статус в разделе **LLM-ассистенты (MCP)**;
- `Invalid MCP token` — перезапустите MCP-сервер в клиенте: Glafira выдаёт новый токен при каждом запуске.

На macOS неподписанную (бета) сборку один раз откройте обычным способом, иначе система может не дать клиенту её запустить. См. [Установка на macOS](getting-started.md#install-macos).
