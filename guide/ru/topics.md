# Кластер и топики

В этой главе — обзор кластера, список топиков, создание и удаление топиков, экран топика и его конфигурация. Под каждым подключением в панели **Подключения** есть ссылки **Обзор кластера** и **Топики**. Каждая открывается в своей вкладке.

<a id="cluster-overview"></a>

## Обзор кластера

**Обзор кластера** показывает состояние кластера на момент загрузки. Чтобы загрузить его заново, нажмите **Обновить**.

- `Cluster ID` — идентификатор кластера.
- **Контроллер** — ID брокера, которого кластер называет контроллером. В кластерах KRaft клиенты не обращаются к контроллерам напрямую: кластер сообщает здесь случайный брокер, а не активный контроллер, и при обновлении он может смениться.
- **Брокеры** — число брокеров.
- **Топики (внутренние)** — все топики, в скобках — сколько из них внутренних.
- **Партиции** — число партиций во всех топиках.
- `Under-replicated` — партиции, у которых не все реплики синхронизированы (входят в ISR). Обычно это значит, что брокер недоступен или не успевает.
- `Offline` — партиции без лидера. Ни запись, ни чтение в них невозможны.

Ненулевое значение `Under-replicated` или `Offline` выделяется.

Ниже — таблица брокеров со столбцами `ID` и **Адрес**. Брокер из поля **Контроллер** отмечен меткой **контроллер**. В кластерах KRaft это тот же случайный брокер, а не активный контроллер. Нажмите на брокер, чтобы увидеть его конфигурацию под таблицей. Конфигурацию брокера можно только просматривать. **Поиск параметра** находит параметр по имени, а **Только изменённые** скрывает параметры со значениями по умолчанию. Значок замка отмечает параметры только для чтения.

<a id="topic-list"></a>

## Список топиков

**Топики** — список топиков кластера. Нажмите на строку, чтобы открыть топик в отдельной вкладке.

Столбцы: **Имя**, **Партиции**, `RF` (фактор репликации), **Сообщений (≈)**, `cleanup.policy` и **Under-repl.** (число недореплицированных партиций). Число сообщений приблизительное: это разница между конечным и начальным оффсетами партиций. Из-за compaction и транзакционных маркеров реальных сообщений меньше. Число сообщений и `cleanup.policy` загружаются только для строк, до которых вы прокрутили список.

Панель над списком:

- **Поиск (или /regex/)** — введите часть имени, чтобы найти топики; регистр не важен. Для поиска по регулярному выражению заключите его в косые черты, например `/^orders\..*/`.
- **Внутренние** — показать внутренние топики, например `__consumer_offsets`. Они отмечены меткой **(внутр.)**.
- Список автообновления — **Автообновление: выкл.**, **каждые 10 с** или **каждые 30 с**.
- **Обновить** — сразу перезагрузить список и число сообщений.

Рядом приложение показывает, сколько топиков подходит под поиск и сколько их всего. На подключениях **Только чтение** кнопки **Создать топик** и **Выбрать** скрыты.

<a id="create-topic"></a>

## Создание топика

1. В списке топиков нажмите **Создать топик**. Над списком откроется форма **Новый топик**.
2. Заполните поле **Имя топика**. В имени допустимы латинские буквы, цифры, `.`, `_` и `-`, длина — до 249 символов. Если в имени есть и `.`, и `_`, форма предупредит: имена метрик Kafka у такого топика могут совпасть с другими.
3. Укажите число в поле **Партиции**. Партиции читаются параллельно, порядок гарантирован только внутри одной партиции. Число партиций можно потом увеличить, но не уменьшить.
4. Укажите **Фактор репликации** — сколько копий каждой партиции хранят брокеры. Он не может быть больше числа брокеров; число брокеров показано под полем. По умолчанию — 3 или число брокеров, если их меньше. `-1` — значение по умолчанию брокера.
5. Выберите **Пресет**:
   - **delete (по умолчанию)** — старые сообщения удаляются по времени;
   - `compact` — хранится только последнее значение каждого ключа;
   - `compact + delete` — и то и другое;
   - **тестовый (retention 1 ч)** — сообщения хранятся один час.
6. При необходимости заполните **Доп. конфиги (key=value)**, по одному на строку, например `retention.ms=86400000`. Они перекрывают пресет. Строки, начинающиеся с `#`, пропускаются.
7. Нажмите **Создать**.

Когда форма заполнена верно, под ней показывается такая же команда `kafka-topics.sh`. Её можно скопировать, например, чтобы создать такой же топик в другом кластере.

На prod-подключении создание нужно подтвердить вводом имени подключения. После создания откроется вкладка топика.

<a id="delete-topics"></a>

## Удаление топиков

Чтобы удалить один топик, откройте его и нажмите **Удалить топик**. Введите имя топика и нажмите **Удалить**. Вкладка топика закроется.

Чтобы удалить несколько топиков сразу:

1. В списке топиков нажмите **Выбрать**. Рядом с именами появятся флажки.
2. Отметьте топики. Внутренние топики отметить нельзя.
3. Нажмите кнопку удаления — на ней указано число отмеченных топиков.
4. Проверьте список имён, введите их число и нажмите **Удалить**.

**Отменить выбор** убирает флажки.

На prod-подключении при любом способе удаления нужно ввести ещё и имя подключения.

Удаление необратимо: данные теряются. Если часть топиков удалить не удалось, например из-за нехватки прав, приложение покажет их с причиной. Остальные топики будут удалены.

<a id="topic-details"></a>

## Экран топика

Во вкладке топика показаны число партиций, фактор репликации и примерное число сообщений. Кнопки вверху:

- **Обновить** — перезагрузить данные топика.
- **Отправить сообщение** — открыть **Producer** с этим топиком. См. [Producer](producer.md).
- **Читать как группа** — запустить consumer-сессию для этого топика. См. [Consumer-сессии](consumer-sessions.md).

На подключениях **Только чтение** обе кнопки недоступны.

Во второй строке — действия, которые меняют топик. Она скрыта на подключениях только для чтения и у внутренних топиков.

- **Добавить партиции** — введите новое общее число и нажмите **Увеличить**. Уменьшить число партиций нельзя. После увеличения сообщения с одним ключом могут попасть в другую партицию, и порядок по ключу нарушится.
- **Очистить** — удалить все сообщения до текущего конца выбранных партиций. Сам топик остаётся. Отметьте партиции, введите имя топика и нажмите **Очистить партиции**. Очистка работает, только если в `cleanup.policy` есть `delete`; иначе кнопка недоступна и показана причина. У топика с `compact,delete` очистка удалит и последние значения ключей.
- **Удалить топик** — см. [Удаление топиков](topics.md#delete-topics).

На prod-подключении каждое из этих действий также спрашивает имя подключения.

Вкладки ниже:

- **Сообщения** — просмотр сообщений. См. [Просмотр сообщений](browse.md).
- **Партиции** — таблица партиций: **Лидер**, **Реплики**, `ISR` (синхронизированные реплики), начальный (`Low`) и конечный (`High`) оффсеты и число сообщений. У партиции без лидера показано **нет**.
- **Конфигурация** — параметры топика. См. [Конфигурация топика](topics.md#topic-config).
- **Consumer groups** — consumer groups с закоммиченными оффсетами в этом топике: **Состояние**, **Партиций с коммитами** и **Лаг**. Нажмите на группу, чтобы открыть её. См. [Consumer groups](groups.md).

<a id="topic-config"></a>

## Конфигурация топика

Во вкладке **Конфигурация** перечислены все параметры топика. Столбцы:

- **Параметр** — имя параметра. Жирным выделены параметры, заданные явно: на топике или в конфигурации брокера.
- **Значение** — текущее значение. Секретные значения скрыты как `••••••`.
- **Источник** — откуда взято значение. Например, `DynamicTopic` — задано на этом топике, `StaticBroker` и `DynamicBroker` — из конфигурации брокера, `Default` — значение Kafka по умолчанию.

**Поиск параметра** находит параметр по имени, а **Только изменённые** оставляет только выделенные жирным. Значок замка отмечает параметры только для чтения. Значок `?` рядом с именем объясняет параметр.

<a id="edit-config"></a>

## Изменение конфигурации

1. Во вкладке **Конфигурация** нажмите **Редактировать**. На подключениях **Только чтение** этой кнопки нет.
2. Измените значения в столбце **Значение**. Параметры только для чтения и секретные изменить нельзя. Чтобы убрать собственное значение топика, нажмите **к default**: тогда действует значение брокера. Пустое значение не допускается.
3. Нажмите **Проверить изменения**. Приложение покажет каждое изменение в виде «было → стало»; **по умолчанию** значит, что значение сбрасывается.
4. Нажмите **Применить** или **Назад**, чтобы продолжить правку.

Пока вы не примените изменения, в кластере ничего не меняется. **Отменить правки** отменяет все правки. Пока есть несохранённые правки, кнопка **Закрыть редактор** недоступна. На prod-подключении изменения нужно подтвердить вводом имени подключения.

Отправляются только изменённые параметры, остальные остаются как были. Брокер проверяет значения и отклоняет неверные с ошибкой.

<a id="config-parameters"></a>

## Параметры топика

У топика Kafka десятки параметров. Значки `?` в таблице конфигурации объясняют каждый из них. Чаще всего нужны эти:

- `cleanup.policy` — что происходит со старыми данными. `delete` удаляет старые сегменты по времени или размеру. `compact` хранит только последнее значение каждого ключа. `compact,delete` — и то и другое.
- `retention.ms` — сколько хранятся сообщения, в миллисекундах. По умолчанию `604800000` (7 дней); `-1` — хранить бессрочно. Действует, если в `cleanup.policy` есть `delete`.
- `retention.bytes` — максимальный размер каждой партиции, после которого удаляются старые сегменты. По умолчанию `-1` — без ограничения по размеру.
- `segment.ms` и `segment.bytes` — когда брокер начинает новый сегмент лога. Хранение и compaction работают с сегментами целиком, поэтому сообщение может храниться дольше `retention.ms`, пока его сегмент не закрыт.
- `min.insync.replicas` — сколько реплик должны подтвердить запись при `acks=all`. Обычно 2 при факторе репликации 3.
- `max.message.bytes` — самый большой пакет, который брокер примет в этот топик. По умолчанию около 1 MB. Producer должен допускать такой же размер (`max.request.size`).
- `compression.type` — как брокер хранит сообщения. `producer` сохраняет сжатие, которое выбрал producer.
- `message.timestamp.type` — `CreateTime` (метка времени от producer) или `LogAppendTime` (время записи на брокер). Именно это время показывается при просмотре сообщений.
- `delete.retention.ms` — сколько маркеры удаления (сообщения со значением null) хранятся в топике с compaction. По умолчанию — 1 день.

Некоторые параметры есть только в новых версиях Kafka, а некоторые устарели — подсказка `?` говорит об этом, где это важно. Параметры tiered storage, например `remote.storage.enable`, работают, только если кластер его поддерживает.
