# Consumer groups

Consumer group — это набор потребителей, которые делят между собой чтение топиков. Kafka отдаёт каждую партицию одному участнику группы и хранит для каждой партиции оффсет, который группа закоммитила. После перезапуска приложения продолжают чтение с этого оффсета.

Откройте **Consumer groups** у подключения в панели **Подключения**. Группы одного топика есть также на вкладке **Consumer groups** этого топика. См. [Экран топика](topics.md#topic-details).

<a id="group-list"></a>

## Список групп

В списке — все consumer groups кластера. Столбцы:

- **Группа** — ID группы (`group.id`).
- **Состояние** — состояние, которое сообщает Kafka, например `Stable` (участники читают), `Empty` (участников нет), `PreparingRebalance` или `CompletingRebalance` (партиции перераспределяются) и `Dead` (группы больше нет).
- **Участники** — число активных участников.
- `Assignor` — стратегия распределения партиций, например `range`.
- **Лаг** — суммарный лаг группы. См. [Лаг](groups.md#lag).
- **Топики** — топики, в которых у группы есть закоммиченные оффсеты.

Введите текст в поле **Поиск группы**, чтобы оставить группы, ID которых его содержит; регистр не важен. Список состояний рядом оставляет группы в одном состоянии; **Все состояния** снимает этот фильтр. Счётчик показывает, сколько групп показано и сколько их всего.

Участники, assignor и лаг загружаются только для видимых строк, по мере прокрутки. Пока данных нет, в ячейке `…`. Если загрузить их не удалось, в ячейке `—`; наведите на неё указатель, чтобы увидеть причину.

**Обновить** заново загружает список и данные в нём. Если часть брокеров не ответила, появится предупреждение, что список может быть неполным.

<a id="lag"></a>

## Лаг

Лаг — сколько сообщений группа ещё не прочитала. Для каждой партиции это конец лога минус закоммиченный оффсет. Лаг не бывает меньше нуля.

Лаг зависит только от закоммиченных оффсетов. Активный потребитель мог прочитать дальше, чем закоммитил, поэтому настоящий лаг может быть меньше. После следующего коммита группы лаг уменьшится.

Партиция без закоммиченного оффсета показывает **нет коммита** и не входит в сумму. Суммарный лаг группы показывается как `—`, если у группы нет коммитов вовсе (**нет коммитов**) или если оффсеты какой-то партиции не удалось получить (**лаг неизвестен: ошибка оффсетов партиций**).

Лаг считает оффсеты, а не сообщения. В топиках с compaction или транзакциями часть оффсетов не содержит видимых сообщений, поэтому непрочитанных сообщений может быть меньше, чем показывает лаг.

Значения — снимок на момент загрузки. Чтобы следить за лагом, откройте группу и включите автообновление.

<a id="group-details"></a>

## Детали группы

Нажмите на группу в списке, чтобы открыть её вкладку. Вверху — сводка: состояние, число участников и assignor.

- **Автообновление** — **Автообновление: выкл.**, **каждые 5 с** или **каждые 10 с**.
- **Обновить** — загрузить заново сейчас.
- **Читать как участник** — запустить [consumer-сессию](consumer-sessions.md) в этой группе. В форму сессии попадут ID группы и топики, в которых у неё есть коммиты. На подключениях **Только чтение** кнопка недоступна. Наведите на неё указатель, чтобы увидеть причину.

**Партиции** — партиции, в которых у группы есть коммиты, и партиции, назначенные её участникам. Над таблицей показан суммарный лаг группы. Столбцы: **Топик**, **Партиция**, `Committed` (закоммиченный оффсет), `Log end` (конечный оффсет партиции), **Лаг** и **Участник** (client ID участника, который читает партицию).

**Участники** — активные участники: `Client ID`, **Хост**, `Member ID` и **Назначение** (партиции участника в виде `topic:partition`). Для группы без участников показывается **Нет активных участников.**

Во втором ряду — **Сбросить оффсеты** и **Удалить группу**. На подключениях только для чтения этот ряд скрыт.

<a id="reset-offsets"></a>

## Сброс оффсетов

Сброс оффсетов передвигает закоммиченные оффсеты группы. После этого группа перечитывает сообщения или пропускает их. Сбросить оффсеты можно только у группы без активных участников (состояние `Empty` или `Dead`). Иначе участники перезапишут новые оффсеты своими коммитами. Сначала остановите приложения группы.

1. На вкладке группы нажмите **Сбросить оффсеты**. Пока в группе есть участники, кнопка недоступна; наведите на неё указатель, чтобы увидеть причину.
2. Выберите **Стратегия**. См. [Стратегии сброса](groups.md#reset-strategies).
3. Выберите **Область**. См. [Область сброса](groups.md#reset-scope).
4. Нажмите **Предпросмотр**.
5. Проверьте таблицу и нажмите кнопку применения. На ней указано, сколько партиций изменится.

Предпросмотр ничего не меняет. Для каждой партиции он показывает топик, партицию, **Текущий** (закоммиченный оффсет), **Новый** (целевой оффсет) и `Low / High` (первый и конечный оффсеты партиции). Партиция, для которой целевой оффсет вычислить нельзя, помечена **Нет целевого оффсета — не будет применено** с причиной. Такие партиции пропускаются.

Применяется только план, показанный в предпросмотре. Любое изменение формы скрывает предпросмотр, и нужно снова нажать **Предпросмотр**. На prod-подключении применение просит ввести имя подключения; на остальных выполняется сразу.

Перед применением приложение ещё раз проверяет, что в группе нет участников. После применения **Результат применения** перечисляет партиции с новым оффсетом или ошибкой.

Сброс можно подготовить и из сообщения: см. [Сбросить группу к сообщению](browse.md#reset-group-here). **Закрыть** закрывает панель сброса.

<a id="reset-strategies"></a>

## Стратегии сброса

**Стратегия** задаёт целевой оффсет для каждой партиции из области сброса:

- **С начала (earliest)** — первый оффсет, который ещё хранится. Группа перечитает всё, что есть в топике.
- **С конца (latest)** — конец партиции. Группа пропустит всё накопленное и будет читать только новые сообщения.
- **По времени** — первое сообщение, записанное в момент из поля **Дата и время (локальное)** или позже. В партициях без более новых сообщений целевой оффсет — конец.
- **Конкретный оффсет** — оффсет из поля **Оффсет**, целое число от 0, одинаковый для всех партиций. Если в партиции такого оффсета нет, берётся её первый или конечный оффсет.
- **Сдвиг на ±N** — сдвигает закоммиченный оффсет на число из поля **Сдвиг (±N)**. Отрицательное число — перечитать N сообщений назад, положительное — пропустить N сообщений. Результат не выходит за первый и конечный оффсеты. Партиции без закоммиченного оффсета сдвинуть нельзя, они пропускаются.

Время — местное, с секундами. Kafka находит оффсет по меткам времени сообщений.

<a id="reset-scope"></a>

## Область сброса

**Область** задаёт, какие партиции сбрасываются. У остальных партиций оффсеты не меняются.

- **Вся группа** — все партиции, в которых у группы есть закоммиченные оффсеты. Если коммитов у группы ещё нет, выберите топики.
- **Топики** — все партиции перечисленных топиков, в том числе без коммитов. Разделяйте имена запятыми, пробелами или переводами строк. Так можно задать группе, с какого места начать читать новый для неё топик.
- **Партиции** — только перечисленные партиции. Укажите их в поле **Партиции (топик:партиция)** в виде `topic:partition` через запятую или пробел, например `orders:0, orders:3`.

<a id="delete-group"></a>

## Удаление группы

Удаление группы стирает все её закоммиченные оффсеты. Удалить можно только группу без участников, в состоянии `Empty`.

1. На вкладке группы нажмите **Удалить группу**. Пока в группе есть участники, кнопка недоступна; наведите на неё указатель, чтобы увидеть причину.
2. Для подтверждения введите ID группы. На prod-подключении введите ещё и имя подключения.
3. Нажмите **Удалить**.

После удаления вкладка группы закрывается. Если приложение с этим `group.id` запустится снова, Kafka создаст группу заново. Без закоммиченных оффсетов приложение начнёт с того места, которое задаёт его параметр `auto.offset.reset`: с начала или с конца.

На подключениях **Только чтение** кнопка скрыта.
