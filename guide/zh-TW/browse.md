# 瀏覽訊息

訊息是在主題的**訊息**分頁上瀏覽。瀏覽不會加入消費者群組，也不會提交任何內容，因此叢集不會有任何變更。在**唯讀**連線上也可以瀏覽。若要以群組成員身分讀取，請使用[消費者工作階段](consumer-sessions.md)。

<a id="start-reading"></a>

## 開始讀取

1. 從**主題**清單中開啟一個主題。首先開啟的是**訊息**分頁。
2. 在**起始**中選擇從哪裡開始。請參閱[起始位置](browse.md#start-position)。
3. 視需要設定格式和篩選條件。
4. 按一下**讀取**。

訊息一到達就會顯示在表格中。按鈕旁的狀態列會顯示已掃描多少訊息、有多少符合篩選條件，以及表格中有多少訊息，也會顯示狀態：**正在讀取…**、**已達上限**、**已到達主題結尾**或**已停止**。

未開啟 `Live tail` 時，讀取會在按下**讀取**那一刻的主題結尾停止；如果先達到**上限**，則會提早停止。上限計算的是符合篩選條件的訊息，範圍為 1 到 100000；值越大，讀取越慢。

開啟 `Live tail` 時，讀取到結尾也不會停止：新訊息一寫入就會加入表格。所有舊訊息讀完後，狀態會顯示**正在等待新訊息…**。表格最多保留上限數量的最新訊息，並捨棄最舊的訊息。

**停止**會停止讀取並保留表格。讀取進行時，**讀取**按鈕會變成**重新開始**：它會以目前的設定重新開始，並清除表格。如果與 Broker 的連線中斷，應用程式會自行重新連線，並在狀態列中顯示。

不同分區的訊息會混合顯示在表格中。Kafka 只在單一分區內保證順序。`P` 欄顯示分區，`Offset` 顯示在分區中的位置。勾選 `UTC` 可改以 UTC 而非本機時間顯示時間。

<a id="start-position"></a>

## 起始位置

**起始位置**用於設定在每個分區中從哪裡開始讀取：

- **最新 N 則**：最後 N 則訊息。N 會平均分配給各分區，因此在 100 則訊息、4 個分區的情況下，每個分區最多讀取 25 則。
- **從頭開始**：從仍保存的最舊訊息開始。
- **從偏移量**：在每個分區中從相同的偏移量開始。如果某個分區沒有這個偏移量，則從該分區的開頭或結尾開始讀取。這個模式最適合只有一個分區的情況。
- **從時間**：從時間戳記等於或晚於指定本機時間的第一則訊息開始。在沒有較新訊息的分區中，從結尾開始讀取。
- **最近 X 分鐘**：同上，但從現在往回計算。

顯示**分區：全部**的欄位可將讀取範圍限制在部分分區。請輸入以逗號分隔的分區編號，例如 `0,2`。留空則讀取所有分區。

<a id="filters"></a>

## 篩選條件

篩選條件只會顯示符合的訊息。應用程式仍會從起始位置讀取所有訊息並逐一檢查，因此篩選條件不會加快讀取。所有已填寫的欄位都必須符合。

- **鍵包含**和**值包含**：鍵或值中的文字。
- `regex`：將這些欄位以及標頭值當作規則運算式。
- `Aa`：區分大小寫。預設不區分大小寫。
- **標頭**：訊息含有名稱完全相同的標頭。**標頭值**還會檢查它的值。
- `JSONPath`：針對 JSON 值的條件，例如 `$.order.status == "FAILED"`。如果沒有 `==` 或 `!=`，則路徑只要存在即可，例如 `$.error`。值不是有效 JSON 的訊息不符合條件。
- **開始時間**和**結束時間**：訊息時間戳記在此範圍內，以本機時間計算，包含兩端。

篩選條件檢查的是表格中顯示的文字，也就是解碼後的文字。如果值格式為 `hex`，值篩選條件會搜尋十六進位文字。篩選條件在按下**讀取**時套用；變更後請重新讀取。

篩選條件不會移動起始位置。例如，搭配篩選條件使用**最新 N 則**時，只會在最後 N 則訊息中尋找符合的訊息。若要搜尋整個主題，請選擇**從頭開始**。

<a id="formats"></a>

## 格式

**格式**用於設定鍵和值的解碼方式，**鍵**和**值**分別設定。只會改變顯示方式，不會改變資料。

- `auto`：預設值。有效的 JSON 物件和陣列以 JSON 顯示，其他 UTF-8 文字以字串顯示，二進位資料以十六進位顯示。
- `string`：UTF-8 文字。不是有效 UTF-8 的位元組會被替換為 `�`。
- `json`：在訊息詳細資訊中以縮排顯示 JSON。如果值不是有效的 JSON，詳細資訊會顯示錯誤。
- `hex`：每個位元組以兩個十六進位數字表示。
- `base64`：以 Base64 表示的位元組。

詳細資訊會顯示實際使用的格式，例如 `auto` 偵測到 JSON 時會顯示 `json`。標頭值以文字顯示；二進位的標頭值會以 `0x` 加上十六進位顯示。缺少的鍵或值會顯示為 `null`。

非常大的鍵和值只會顯示一部分，大約是文字的前 1 MB。這也適用於 `hex` 和 `base64`。此時訊息詳細資訊會顯示警告。

<a id="message-details"></a>

## 訊息詳細資訊

按一下某一列，即可在表格旁開啟訊息詳細資訊。上方是分區、偏移量和時間。下方：

- **值**和**鍵**：完整文字，以及格式和以位元組計算的大小。JSON 會以縮排顯示。**複製**會複製文字。
- **標頭**：標頭名稱和值的表格。

表格欄位為 `P`、`Offset`、**時間**、**鍵**、**值**、**標頭**（標頭數量）和**大小**（鍵和值的大小，以位元組計算）。時間是訊息的時間戳記，依主題設定 `message.timestamp.type` 而定，由生產者或 Broker 設定。

<a id="export-messages"></a>

## 複製訊息

Glafira 不會將瀏覽的訊息儲存成檔案。若要將訊息帶出應用程式，請複製它：

- **全部複製為 JSON** 會將整則訊息複製為 JSON：主題、分區、偏移量、時間戳記、鍵、值、標頭和大小。鍵和值以解碼後的內容包含在內，並附上格式。
- **值**或**鍵**旁的**複製**只會複製該段文字。

複製的文字使用讀取時選擇的格式。若要精確複製二進位資料，請以 `hex` 或 `base64` 讀取。非常大的鍵和值只會依顯示的內容複製一部分，即使是 `hex` 和 `base64` 也一樣。請參閱[格式](browse.md#formats)。

<a id="open-in-producer"></a>

## 在 Producer 中開啟

**重新傳送**會在同一個連線的 **Producer** 中開啟這則訊息。表單會填入訊息的主題、鍵、值、標頭和格式。分區交由 Kafka 決定。訊息文字中的預留位置不會被替換：副本會依讀取時的原樣傳送。

不會立即傳送任何內容。請檢查表單，視需要修改，然後在 Producer 中傳送。請參閱 [Producer](producer.md)。

在兩種情況下按鈕會停用，並顯示原因：

- 鍵或值太大，只顯示了一部分；
- 文字不是有效的 UTF-8，解碼時有遺失。請以 `hex` 或 `base64` 讀取，以傳送精確的副本。

在**唯讀**連線上，這個按鈕會隱藏。

<a id="reset-group-here"></a>

## 將群組重設到某則訊息

使用「**在此重設群組…**」可以準備偏移量重設，讓消費者群組從這則訊息開始讀取。

1. 在訊息詳細資訊中按一下**在此重設群組…**。
2. 在清單中選擇群組。清單只會列出已存在的群組。
3. 按一下**前往重設**。

群組分頁會開啟，並已填好重設表單。**策略**為**指定偏移量**，並填入這則訊息的偏移量。**範圍**為**分區**，並填入這則訊息的主題和分區。此時還不會有任何變更：按一下**預覽**查看新的偏移量，再在那裡套用重設。群組不能有作用中的成員。請參閱[消費者群組](groups.md)。

在**唯讀**連線上，這個按鈕會隱藏。
