# 叢集檢查與註記

Glafira 使用一組內建規則檢查叢集，並在物件旁顯示發現的問題：連線樹、主題與消費者群組清單，以及主題和消費者群組的畫面。LLM 助理可以為這些檢查結果補充自己的註記。檢查只會讀取叢集，不會變更其中的任何內容。

<a id="run"></a>

## 執行檢查

開啟連線的**叢集概觀**或**檢查結果**，然後按一下**檢查叢集**。一次檢查最多需要 45 秒：Glafira 會讀取 Broker、分區、主題設定（最多 2000 個主題）與消費者群組（最多 500 個）。如果主題或消費者群組超過上述數量、某些內容無法讀取或 45 秒時間已到，結果會標示為**部分檢查**，檢查結果**檢查不完整**會說明哪些內容沒有讀取。

Glafira 不會自行輪詢叢集：只有在你按一下按鈕或 LLM 助理要求時才會執行檢查。結果會保留到下一次檢查。

<a id="rules"></a>

## 檢查內容

- Broker 與分區：沒有控制器、無法使用與複本不足的分區、單一 Broker 叢集、Leader 分布不均、Leader 不在偏好複本上。
- 主題的持久性：複寫係數為 1、`min.insync.replicas` 大於複寫係數、`min.insync.replicas` 等於複寫係數、`min.insync.replicas` 為 1、不乾淨的 Leader 選舉。
- Broker 設定：自動建立主題、預設複寫係數為 1、預設 `min.insync.replicas` 為 1、各 Broker 之間不一致的重要設定。
- 消費者群組：有延遲的空群組、正在重新平衡的群組、沒有分區的成員、自上次檢查以來增加的延遲。

<a id="severity"></a>

## 嚴重程度與環境

每個檢查結果都有嚴重程度：**嚴重**、**警告**或**資訊**。它取決於連線的環境。例如，複寫係數為 1 在 prod 環境中屬於嚴重，在 stage 環境中屬於警告，在 dev、test 與 local 環境中不會顯示。環境在連線表單中設定。

<a id="tab"></a>

## 「檢查結果」分頁

在**檢查結果**分頁中，檢查結果依規則分組，每一筆都會說明問題與處理方式。可以依**嚴重程度**、**來源**與**物件**篩選，也可以依名稱搜尋。按一下物件名稱會開啟它的畫面。

連線樹以及主題和消費者群組清單中帶數字的標記，會顯示與該物件相關的檢查結果和未關閉的 LLM 註記中，嚴重程度為**嚴重**或**警告**的數量。將指標停在標記上即可查看它們的標題。

<a id="hide"></a>

## 隱藏檢查結果

如果某個物件的檢查結果在預期之內，例如 prod 環境中複寫係數為 1 的測試主題，請按一下**對此物件隱藏**。隱藏的檢查結果不會計入標記，之後的檢查中也會保持隱藏。若要查看已隱藏的結果，請勾選「顯示已隱藏」，在那裡可以按一下**還原**。

<a id="notes"></a>

## LLM 註記

透過 MCP 連線的 LLM 助理（請參閱 [LLM 助理（MCP）](llm-mcp.md#how-it-works)）可以為叢集、Broker、主題或消費者群組留下註記。註記會顯示在「**LLM 註記**」與物件畫面中，並署名用戶端名稱。文字會原樣顯示，不含格式與連結。

- **已解決**與**不相關**會關閉註記，已關閉的註記保留在摺疊的區段中。
- **刪除**會刪除一則註記，**刪除所有 LLM 註記**會刪除此連線的所有註記。
- 註記會在建立 7 天後自動刪除。一個連線最多可以有 200 則未關閉的註記。

<a id="with-llm"></a>

## 與 LLM 助理搭配

助理會使用 `health_check` 工具執行同樣的檢查，並看到同樣的檢查結果，包括帶有標示的已隱藏結果。如果上次檢查不到 5 分鐘，助理會直接取得其結果，不會再次查詢叢集。例如，可以這樣要求：「檢查叢集的健康狀況，並針對最重要的問題留下註記。」
