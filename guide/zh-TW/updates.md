# 更新與診斷

本章說明如何更新應用程式、**關於**畫面、診斷壓縮檔以及如何支持本專案。

<a id="updates"></a>

## 更新

應用程式啟動時，會檢查一次是否有新版本。如果有，分頁上方的通知會顯示其版本。**詳細資訊**會開啟**關於**畫面。如果檢查失敗，例如沒有網際網路連線，則不會顯示任何訊息。

手動檢查：

1. 開啟左側面板底部的**關於**。
2. 在**更新**中按一下**檢查更新**。
3. 如果有新版本，畫面會顯示版本號碼和版本資訊。按一下**安裝並重新啟動**。

應用程式會下載更新、檢查簽章、安裝，然後重新啟動。因網路問題而中斷的下載會自動重試，總共最多三次。如果三次都失敗，應用程式會回報「**更新下載已中斷，請檢查網路後再試一次**」。如果簽章檢查失敗，應用程式會回報「**更新簽章驗證失敗，未安裝更新**」。

安裝時可能會要求輸入系統管理員密碼，因為應用程式是安裝給這台電腦的所有使用者：在 macOS 上透過 `.pkg` 安裝程式，在 Windows 上透過 `.msi` 安裝程式，在 Linux 上透過 `.deb` 或 `.rpm` 套件。沒有系統管理員權限的使用者無法更新這類安裝。

如果正在讀取訊息、有消費者工作階段在執行或正在批次傳送，應用程式會先詢問，並顯示有多少工作階段在執行中。按一下**停止工作階段並更新**可停止它們並繼續，或按**取消**。更新後，連線、設定和其他資料都會保留。

更新會從 GitHub 上的發行頁面下載。如果檢查失敗並顯示「**無法檢查更新**」，請檢查你的網路或 Proxy。「**此 build 未設定更新**」表示這個 build 在建置時沒有更新程式金鑰，例如開發或測試用的 build。這種情況請從發行頁面下載新版本：https://github.com/vvnovg/glafira-kafka-releases/releases

組織可以透過原則關閉更新檢查，或將它指向內部鏡像站。關閉檢查時，按一下**檢查更新**後，**更新**區段會顯示「**更新由你的組織管理**」。與「**此 build 未設定更新**」一樣，這則訊息只會在按下按鈕後出現；在這些情況下，啟動時的檢查不會顯示任何內容。

## 關於

開啟左側面板底部的**關於**。在 macOS 上，也可以在「輔助說明」選單中找到**關於 Glafira**。

畫面會顯示應用程式的簡短說明，以及：

- **版本**：版本號碼；**Build**：此 build 所用原始碼的識別碼。提出支援要求時請附上這兩項。
- **系統**：作業系統和處理器架構。
- **授權**：Apache 2.0，連結會在瀏覽器中開啟授權全文。
- **組織原則**：**已設定**或**無**。原則中的錯誤會列在下方。
- 「**資料：**」後顯示的是存放連線設定檔、範本、歷程記錄、設定的資料夾。
- 「**日誌：**」後顯示的是存放日誌檔案的資料夾。請參閱[日誌](troubleshooting.md#logs)。

這個畫面上還有**更新**和**診斷**區段。

<a id="diagnostics"></a>

## 診斷壓縮檔

診斷壓縮檔會收集支援人員了解問題所需的資訊。建立方式：

1. 開啟**關於**。
2. 在**診斷**中按一下**收集診斷資訊**。在 macOS 上，也可以在「輔助說明」選單中選擇**收集診斷資訊…**。
3. 選擇檔案的儲存位置。建議的名稱為 `diagnostics-<date>.zip`。

壓縮檔儲存後，畫面會顯示其路徑。ZIP 檔案包含：

- `info.json`：應用程式版本和 build、作業系統、資料和日誌資料夾的路徑、原則狀態；
- `connections.json`：連線設定檔，包括名稱、環境、Bootstrap 伺服器、通訊協定、SASL 使用者名稱、憑證檔案路徑、額外屬性和逾時；
- `logs/`：應用程式的日誌檔案。

壓縮檔中不含密碼：密碼保存在系統金鑰儲存區中，而含有密碼和機密的額外屬性在儲存連線時就會被拒絕。憑證檔案也不會包含在內。主機名稱、使用者名稱和檔案路徑會以純文字儲存，而日誌中包含 Kafka 錯誤訊息裡的 Broker 位址。將壓縮檔傳送到公司外部之前，請先檢查其內容。

應用程式不會自行傳送任何內容。請自行將壓縮檔附加到你的支援要求中，請參閱[聯絡支援人員](troubleshooting.md#support)。
