# 叢集與主題

本章說明叢集概觀、主題清單、建立和刪除主題、主題畫面以及主題設定。**連線**面板中每個連線下方都有**叢集概觀**和**主題**的連結，各自在獨立的分頁中開啟。

<a id="cluster-overview"></a>

## 叢集概觀

**叢集概觀**會顯示載入當下的叢集狀態。按一下**重新整理**可重新載入。

- `Cluster ID`：叢集識別碼。
- **控制器**：叢集回報為控制器的 Broker ID。在 KRaft 叢集中，用戶端不會直接與控制器通訊：叢集在這裡回報的是隨機的 Broker，而不是作用中的控制器，而且每次重新整理都可能不同。
- **Broker**：Broker 數量。
- **主題（內部）**：所有主題的數量，括號中為內部主題的數量。
- **分區**：所有主題的分區總數。
- `Under-replicated`：並非所有複本都已同步（在 ISR 中）的分區。通常是有 Broker 停止運作或跟不上。
- `Offline`：沒有 Leader 的分區。任何人都無法寫入或讀取這些分區。

`Under-replicated` 或 `Offline` 的值不為零時會醒目標示。

下方是 Broker 表格，包含 `ID` 和**位址**。**控制器**欄位中的 Broker 會標示為**控制器**。在 KRaft 叢集中，這是同一個隨機的 Broker，而不是作用中的控制器。按一下 Broker，即可在表格下方查看它的設定。Broker 設定只能檢視。使用**搜尋參數**可依名稱尋找參數，使用**僅顯示已變更**可隱藏預設值的參數。鎖頭圖示表示唯讀參數。

<a id="topic-list"></a>

## 主題清單

**主題**會列出叢集中的主題。按一下某一列，即可在獨立的分頁中開啟該主題。

欄位包括**名稱**、**分區**、`RF`（複寫係數）、**訊息數（≈）**、`cleanup.policy` 和**複本不足**（複本不足的分區數量）。訊息數是近似值，也就是各分區結尾和起始偏移量的差。Compaction 和交易標記會使實際數量較少。訊息數和 `cleanup.policy` 只會針對捲動到的列載入。

工具列控制項：

- **搜尋（或 /regex/）**：輸入名稱的一部分即可尋找主題，不區分大小寫。若要使用規則運算式搜尋，請將它放在兩個斜線之間，例如 `/^orders\..*/`。
- **內部**：顯示內部主題，例如 `__consumer_offsets`。這些主題會標示為「**（內部）**」。
- 自動重新整理清單：**自動重新整理：關閉**、**每 10 秒**或**每 30 秒**。
- **重新整理**：立即重新載入清單和訊息數。

工具列旁會顯示符合搜尋條件的主題數和總數。在**唯讀**連線上，**建立主題**和**選取**按鈕會隱藏。

<a id="create-topic"></a>

## 建立主題

1. 在主題清單中按一下**建立主題**。清單上方會開啟**新增主題**表單。
2. 輸入**主題名稱**。名稱可包含拉丁字母、數字、`.`、`_` 和 `-`，最多 249 個字元。如果名稱同時含有 `.` 和 `_`，表單會發出警告：這類主題的 Kafka 指標名稱可能與其他主題衝突。
3. 設定**分區數**。分區會平行讀取，而順序只在單一分區內有保證。分區數之後可以增加，但永遠無法減少。
4. 設定**複寫係數**，也就是 Broker 為每個分區保留幾份複本。它不能大於 Broker 數量，表單會在欄位下方顯示 Broker 數量。預設為 3；如果 Broker 少於 3 個，則為 Broker 數量。`-1` 表示使用 Broker 的預設值。
5. 選擇**預設集**：
   - **delete（預設）**：舊訊息依時間刪除。
   - `compact`：每個鍵只保留最新的值。
   - `compact + delete`：兩者兼具。
   - **test（保留 1 小時）**：訊息保留一小時。
6. 視需要新增**額外設定（key=value）**，每行一個，例如 `retention.ms=86400000`。這些設定會覆寫預設集。以 `#` 開頭的行會被忽略。
7. 按一下**建立**。

表單內容有效時，會顯示對應的 `kafka-topics.sh` 指令。你可以複製它，例如在另一個叢集中建立相同的主題。

在正式環境連線上，需要輸入連線名稱來確認建立。主題建立後會開啟它的分頁。

<a id="delete-topics"></a>

## 刪除主題

若要刪除一個主題，請開啟它並按一下**刪除主題**。輸入主題名稱確認，然後按**刪除**。主題的分頁會關閉。

一次刪除多個主題：

1. 在主題清單中按一下**選取**。名稱旁會出現核取方塊。
2. 選取主題。內部主題無法選取。
3. 按一下刪除按鈕。按鈕上會顯示已選取的主題數。
4. 檢查名稱清單，輸入主題數量確認，然後按**刪除**。

**取消選取**會隱藏核取方塊。

在正式環境連線上，這兩種刪除方式也都會要求輸入連線名稱。

刪除後無法復原，資料會遺失。如果有些主題沒有刪除，例如因為權限不足，應用程式會列出這些主題和原因。其他主題則會刪除。

<a id="topic-details"></a>

## 主題畫面

主題分頁會顯示分區數、複寫係數和近似的訊息數。上方的按鈕：

- **重新整理**：重新載入主題資料。
- **傳送訊息**：以這個主題開啟 **Producer**。請參閱 [Producer](producer.md)。
- **以群組身分讀取**：為這個主題啟動消費者工作階段。請參閱[消費者工作階段](consumer-sessions.md)。

在**唯讀**連線上，這兩個按鈕會停用。

第二列是會變更主題的動作。在唯讀連線上和內部主題中會隱藏。

- **新增分區**：輸入新的總數，然後按一下**增加**。分區數無法減少。增加分區後，相同鍵的訊息可能會進入不同的分區，因此依鍵的順序會被打亂。
- **清除**：刪除所選分區中直到目前結尾的所有訊息，主題本身會保留。選取分區，輸入主題名稱，然後按一下**清除分區**。只有在 `cleanup.policy` 包含 `delete` 時才能清除；否則按鈕會停用並顯示原因。對於 `compact,delete` 主題，清除也會刪除各個鍵的最新值。
- **刪除主題**：請參閱[刪除主題](topics.md#delete-topics)。

在正式環境連線上，這些動作都會要求輸入連線名稱。

下方的分頁：

- **訊息**：瀏覽訊息。請參閱[瀏覽訊息](browse.md)。
- **分區**：列出每個分區的表格，包含 **Leader**、**複本**、`ISR`（同步中的複本）、起始（`Low`）和結尾（`High`）偏移量以及訊息數。沒有 Leader 的分區會顯示「**無**」。
- **設定**：主題參數。請參閱[主題設定](topics.md#topic-config)。
- **消費者群組**：已為這個主題提交偏移量的消費者群組，包含**狀態**、**有提交的分區**和**延遲**。按一下群組即可開啟。請參閱[消費者群組](groups.md)。

<a id="topic-config"></a>

## 主題設定

**設定**分頁會列出所有主題參數，共有三欄：

- **參數**：參數名稱。粗體名稱表示已明確設定，設定在主題上或 Broker 設定中。
- **值**：目前的值。敏感值會隱藏為 `••••••`。
- **來源**：值的來源。例如 `DynamicTopic` 是在這個主題上設定的，`StaticBroker` 和 `DynamicBroker` 來自 Broker 設定，`Default` 是 Kafka 的預設值。

使用**搜尋參數**可依名稱尋找參數，使用**僅顯示已變更**可只顯示粗體參數。鎖頭圖示表示唯讀參數。名稱旁的 `?` 圖示會說明該參數。

<a id="edit-config"></a>

## 變更設定

1. 在**設定**分頁上按一下**編輯**。在**唯讀**連線上，這個按鈕會隱藏。
2. 在**值**欄中變更值。唯讀和敏感參數無法編輯。若要移除主題自己的值，請按一下**還原為預設值**，之後就會套用 Broker 的值。不允許空值。
3. 按一下**檢查變更**。應用程式會以「舊值 → 新值」顯示每項變更；「**預設**」表示值會被還原。
4. 按一下**套用**，或按**返回**繼續編輯。

套用之前，叢集中不會有任何變更。**捨棄編輯**會取消所有編輯。有未儲存的編輯時，**關閉編輯器**會停用。在正式環境連線上，需要輸入連線名稱來確認變更。

只會傳送你變更的參數，主題的其他參數保持不變。Broker 會檢查這些值，並以錯誤拒絕無效的值。

<a id="config-parameters"></a>

## 主題參數

Kafka 主題有數十個參數。設定表格中的 `?` 圖示會逐一說明。最常用的是這些：

- `cleanup.policy`：舊資料的處理方式。`delete` 會依時間或大小移除舊的日誌區段。`compact` 每個鍵只保留最新的值。`compact,delete` 兩者都做。
- `retention.ms`：訊息保留多久，單位為毫秒。預設為 `604800000`（7 天）；`-1` 表示永久保留。在 `cleanup.policy` 包含 `delete` 時生效。
- `retention.bytes`：刪除舊日誌區段前每個分區的最大大小。預設值 `-1` 表示不限大小。
- `segment.ms` 和 `segment.bytes`：Broker 何時開始新的日誌區段。保留和 Compaction 都以整個日誌區段為單位，因此在區段關閉之前，訊息保留的時間可能超過 `retention.ms`。
- `min.insync.replicas`：使用 `acks=all` 時，必須有多少個複本確認寫入。複寫係數為 3 時通常設為 2。
- `max.message.bytes`：Broker 為這個主題接受的最大批次。預設約為 1 MB。生產者也必須允許相同的大小（`max.request.size`）。
- `compression.type`：Broker 儲存訊息的方式。`producer` 會保留生產者的壓縮方式。
- `message.timestamp.type`：`CreateTime`（生產者設定的時間）或 `LogAppendTime`（Broker 寫入訊息的時間）。這是瀏覽訊息時顯示的時間。
- `delete.retention.ms`：刪除標記（值為 null 的訊息）在經過 Compaction 的主題中保留多久。預設為 1 天。

有些參數只存在於較新的 Kafka 版本中，有些則已淘汰。必要時 `?` 圖示會加以說明。分層儲存的參數（例如 `remote.storage.enable`）只有在叢集支援時才有效。
