# Producer

**Producer** 用來將訊息傳送到 Kafka：可以從表單一次傳送一則，也可以一次傳送多則。可從**連線**面板中的連線開啟，或在主題分頁上按**傳送訊息**開啟，此時會自動填入主題。每個連線都有自己的 Producer 分頁。

在**唯讀**連線上，傳送按鈕會隱藏，但仍可檢視範本和歷程記錄。Producer 開啟時會顯示以下警告：**連線為唯讀，無法傳送。**

<a id="send-message"></a>

## 傳送訊息

1. 輸入**主題**。欄位會建議叢集中的主題，不含內部主題。
2. 視需要輸入**分區**編號。欄位顯示**自動**時，分區會依鍵選擇：相同鍵的訊息會進入相同的分區，與 Java 用戶端相同。沒有鍵的訊息會進入隨機的分區。
3. 填寫**鍵**和**值**，並選擇它們的格式。請參閱[鍵和值的格式](producer.md#key-value-formats)。
4. 視需要新增標頭。
5. 按一下**傳送**。

傳送成功後，表單下方會有一行顯示訊息的分區、偏移量和時間。`acks` 設為 `0` 時，Broker 不會傳回偏移量，會改為顯示 `—`。

如果分區編號太大，或 Broker 未在連線逾時內確認訊息，應用程式會顯示錯誤。不存在的主題也會產生錯誤，除非 Broker 會自動建立主題（`auto.create.topics.enable`）。關閉自動建立時，這個錯誤最多可能需要約 30 秒（連線逾時）才會出現。表單中的錯誤，例如無效的 JSON 或未知的預留位置，會在傳送任何內容之前顯示。

在正式環境連線上傳送時，需要輸入連線名稱，並按**傳送到正式環境**確認。請參閱[環境與正式環境](connections.md#environments)。

**清除表單**會清空表單，並將 Producer 設定還原為預設值。主題會保留。

<a id="key-value-formats"></a>

## 鍵和值的格式

**鍵格式**和**值格式**用於設定如何將欄位中的文字轉換為位元組：

- `string`：原樣傳送文字，使用 UTF-8。
- `json`：檢查文字是否為有效的 JSON，然後依輸入的內容傳送，不重新排版。
- `hex`：每個位元組兩個十六進位數字，例如 `48656c6c6f`。空格和換行會被忽略。
- `base64`：以標準 Base64 表示的位元組。
- `null`：完全沒有鍵或值。欄位為空，輸入文字後格式會切換為 `string`。

鍵的預設格式為 `null`，值的預設格式為 `json`。若要傳送有鍵的訊息，直接輸入鍵即可，格式會變成 `string`。空字串仍然是鍵，而不是沒有鍵：如果選擇 `string` 並將欄位留空，所有這類訊息都會得到相同的雜湊值，進入同一個分區。

值為 `null` 的訊息是 tombstone（墓碑訊息）。在 `cleanup.policy=compact` 的主題中，它會告訴 Kafka 移除相同鍵的較舊訊息。

<a id="headers"></a>

## 標頭

標頭是隨訊息一起傳送的名稱與值配對。按一下**新增標頭**新增一列，然後填寫**名稱**、**值**和**格式**。`×` 按鈕會移除該列。

標頭值的格式為 `string`（UTF-8 文字）或 `hex`（以十六進位數字表示的位元組）。名稱為空的列不會傳送。Kafka 允許多個同名的標頭，這些標頭都會傳送。

預留位置可用於標頭值，但不能用於標頭名稱。

<a id="placeholders"></a>

## 預留位置

每次傳送時，預留位置都會被替換成值。預留位置可用於鍵、值和標頭值。清單顯示在標頭下方：

- `{{uuid}}`：新的隨機 UUID，例如 `0b6f6f2c-3c1e-4a8e-9a54-2f0d6f1d7c21`。
- `{{now}}`：目前的 UTC 時間，採用含毫秒的 ISO 8601 格式，例如 `2026-10-15T12:30:00.000Z`。
- `{{nowMillis}}`：目前的時間，以自 1970-01-01 UTC 起的毫秒數表示。
- `{{seq}}`：批次中副本的編號，從 0 開始。單次傳送時為 `0`。
- `{{randomInt 1 100}}`：介於兩個數字之間的隨機整數，包含兩端。
- `{{randomString 8}}`：指定長度的隨機字串，由拉丁字母和數字組成，長度最多 100000。
- `{{env NAME}}`：環境變數 `NAME` 的值。如果未設定，不會傳送任何內容，並會顯示錯誤。

大括號內可以有空格。未知的預留位置或缺少 `}}` 時，會以錯誤停止傳送。若要以文字傳送 `{{`，請寫成 `\{{`。

使用 `json` 格式時，會在替換預留位置後檢查 JSON。產生文字的預留位置需要加引號：`{"id": "{{uuid}}"}`。數字則不需要：`{"n": {{seq}}}`。

`{{env NAME}}` 讀取的是 Glafira 程序的環境。如果你從 Dock 或「開始」功能表啟動 Glafira，只在終端機設定檔中設定的變數可能會不存在。

當訊息來自[在 Producer 中開啟](browse.md#open-in-producer)或歷程記錄時，其中的每個 `{{` 都會寫成 `\{{`。如此一來，訊息會完全依原樣傳送，不會替換任何內容。

<a id="templates"></a>

## 範本

範本會儲存整個表單：主題、分區、鍵、值、標頭、格式和 Producer 設定。預留位置會依原樣儲存，並在每次傳送時替換。

若要儲存範本，請按一下**另存為範本**，輸入**範本名稱**，然後按**儲存**。主題可以留空。範本預設屬於這個連線。勾選**適用於所有連線**可讓範本顯示在每個連線上；這類範本在清單中會標示為「**（所有連線）**」。

若要使用範本，請在**範本**清單中選擇。表單會被範本取代。傳送前可以編輯表單，範本不會改變。

儲存一律會建立新的範本。若要修改範本，請載入它，編輯表單，以新名稱儲存，再刪除舊範本。若要刪除所選範本，請按一下**刪除範本**，再按**刪除**確認。

連線的範本會隨連線一起刪除。

<a id="history"></a>

## 歷程記錄

「**歷程記錄（最近 100 則）**」會列出這個連線最近 100 次單筆傳送，最新的在最前面。批次傳送的訊息不會加入。每一列會顯示時間、主題、分區和偏移量，以及鍵的開頭。

歷程記錄會儲存傳送時的訊息，其中的預留位置已經替換。**重新傳送**會將訊息連同其 Producer 設定載入表單。在你按一下**傳送**之前，不會傳送任何內容。副本會完全依儲存的內容傳送：例如，會再次傳送相同的 UUID。

超過 64 KB 的鍵、值或標頭值只會儲存一部分。對於這類列，**重新傳送**會停用。

歷程記錄以純文字儲存在這台電腦上，包括 `{{env NAME}}` 的值。如果這一點很重要，請不要透過 Producer 傳送機密。連線的歷程記錄會隨連線一起刪除。

<a id="batch-copies"></a>

## 依表單傳送 N 份

表單下方的**批次傳送**可在一次執行中傳送大量訊息。在**依表單傳送 N 份**模式下，會依指定的次數傳送表單。

1. 依單次傳送的方式填寫表單。
2. 選擇**依表單傳送 N 份**，並輸入**份數**，範圍為 1 到 1000000。
3. 視需要設定**速率**。請參閱[傳送速率](producer.md#batch-rate)。
4. 按一下**開始**。

每一份都會個別替換預留位置。`{{seq}}` 是份序號，從 0 到 N−1，因此每則訊息都可以有自己的鍵，例如 `order-{{seq}}`。開始執行前，會先以第一份檢查預留位置錯誤。

執行期間，面板會顯示已傳送多少訊息和失敗多少訊息。結束時會顯示**已完成**。錯誤會連同份序號（從 1 開始計算）一起列出。清單會顯示前 20 個錯誤；如果更多，下方的註記會顯示總數。

**取消**會停止執行。尚未離開應用程式的訊息不會傳送，面板會顯示其數量。應用程式最多會等待 2 秒，讓 Broker 確認已傳送的訊息。仍未確認的訊息會計為錯誤，因為無法得知它們是否已寫入。關閉 Producer 分頁也會停止執行。

在正式環境連線上，執行前會要求輸入連線名稱，並按**在正式環境開始**確認。

<a id="batch-file"></a>

## 從檔案傳送

在**從檔案**模式下，檔案的每一行或每一列都會成為一則訊息。支援的檔案為 JSON Lines（`.jsonl`、`.ndjson`）和 CSV（`.csv`）。

1. 在上方表單中輸入**主題**。所有訊息都會傳送到這個主題。
2. 選擇**從檔案**，然後按一下**選擇檔案…**。
3. 按一下**開始**。

表單中的鍵、值、標頭和分區不會使用，預留位置也不會替換。但會套用表單中的 Producer 設定。

在 JSON Lines 中，每一行都是一個 JSON 物件，例如 `{"key": "k1", "value": {"id": 1}, "headers": {"source": "test"}, "partition": 0}`。所有欄位都是選填：

- `key` 和 `value`：JSON 字串會以其文字傳送，不含引號。其他任何 JSON 值（例如物件或數字）會以 JSON 文字傳送。`null` 或缺少該欄位表示沒有鍵或值。
- `headers`：值為字串的物件。
- `partition`：分區編號。如果沒有，分區會依鍵選擇。

空行會被略過。檔案必須使用 UTF-8。

在 CSV 中，第一列是欄位名稱。`value` 欄為必要欄位；`key`、`partition` 和 `header.NAME` 欄為選填，例如 `header.source`。`key` 儲存格為空表示沒有鍵，標頭儲存格為空表示沒有該標頭。`value` 儲存格為空會傳送空值，而不是 `null`，因此無法從 CSV 傳送 tombstone。

檔案以串流方式讀取，因此事先不知道總數，會顯示為 `—`。大於 16 MB 的行或記錄、無效的 JSON 或負數的分區，都會計為該行的錯誤，然後繼續執行下一行。錯誤會連同行號一起顯示。

<a id="batch-rate"></a>

## 傳送速率

**速率**會將批次限制為每秒指定數量的訊息。請輸入大於或等於 1 的整數。欄位留空表示**不限**。

訊息會平均分散在時間上：每秒 10 則訊息時，大約每 100 ms 送出一則。使用此限制可避免共用叢集負載過重，或模擬穩定的負載。

沒有限制時，應用程式會以 Broker 能接受的最快速度傳送。速率適用於兩種批次模式。

<a id="producer-settings"></a>

## Producer 設定

**Producer 設定**適用於單次傳送和批次傳送，並會儲存在範本和歷程記錄中。

`acks` 設定必須有多少個複本確認寫入：

- `all`：預設值。Leader 會等待所有同步中的複本。這是最安全的選擇。如果同步中的複本少於主題設定 `min.insync.replicas` 的要求，寫入會失敗。
- `1`：只有 Leader 確認。速度較快，但如果 Leader 在 Follower 複製訊息之前故障，訊息可能會遺失。
- `0`：生產者不等待確認。訊息可能會遺失，且不會傳回偏移量。

**壓縮**會壓縮訊息批次：`none`（預設）、`gzip`、`snappy`、`lz4` 或 `zstd`。壓縮會耗用一些 CPU，以節省網路流量和磁碟空間。`zstd` 和 `lz4` 是常見的選擇。對於單則小訊息，效益不大。

**冪等性**會設定 `enable.idempotence`。它可以防止用戶端在網路錯誤後重試傳送時產生重複訊息。它要求 `acks` 設為 `all`；如果是其他值，應用程式會顯示錯誤，且不會傳送任何內容。
