# 連線

連線是一個 Kafka 叢集的已儲存設定檔，包含位址、安全性設定和密碼。連線列在左側的**連線**面板中。你可以把連線分類到資料夾，也可以透過匯出和匯入將連線移到另一台電腦。

<a id="create"></a>

## 建立連線

1. 按一下**連線**面板標題列中的 `+`（**新增連線**）。若要直接在資料夾中建立連線，請開啟資料夾選單，選擇**在此新增連線**。
2. 輸入**名稱**。名稱會顯示在面板和分頁標題中。
3. 在 **Bootstrap 伺服器**中輸入一個或多個 `host:port` 格式的位址，以逗號分隔，例如 `kafka1:9092,kafka2:9092`。只要有一個可連線的 Broker 就夠了，用戶端會自行找到其他 Broker。
4. 選擇**通訊協定**，並填寫它新增的欄位。請參閱[安全性通訊協定](connections.md#security)。
5. 視需要選擇**資料夾**、**環境**，以及名稱旁圓點的**顏色**。
6. 按一下**測試連線**，然後按**儲存**。

儲存後，表單會關閉並開啟叢集概觀。

另外兩個欄位用於特殊情況。**要求逾時（ms）**，即等待 Broker 回應的時間，預設為 `30000` ms，最小值為 `1000`。網路較慢或使用 VPN 時請調高此值。**額外的 librdkafka 屬性**可接受任何 librdkafka 設定，格式為 `key=value`，每行一個。以 `#` 開頭的行會被忽略。這裡不能填寫密碼和金鑰：名稱含有 `password` 或 `secret` 的屬性，以及 `sasl.jaas.config`、`ssl.key.pem` 和 `ssl.keystore.key`，在儲存時會被拒絕。

之後若要變更連線，請按一下名稱旁的 `✎`（**編輯連線**）。若要刪除連線，請開啟表單，按一下**刪除**，再按**是，刪除**確認。

<a id="test"></a>

## 測試連線

**測試連線**會逐步檢查表單中的設定，並在第一個失敗的步驟停止：

1. **設定**：位址、憑證檔案、密碼和 SASL 使用者名稱。
2. **DNS / TCP**：主機名稱可以解析，且至少能與一台 Bootstrap 伺服器建立 TCP 連線。
3. **Kafka（TLS、SASL、中繼資料）**：TLS 交握和 SASL 登入成功，且 Broker 傳回中繼資料。成功時，此步驟會顯示 Broker 和主題的數量。

測試使用表單中目前的值，包括已輸入但尚未儲存的密碼。不會儲存任何內容，也不會變更叢集。如果某個步驟失敗，其下方會顯示錯誤文字和詳細資訊。常見錯誤的說明請參閱[無法連線](troubleshooting.md#cannot-connect)。

<a id="security"></a>

## 安全性通訊協定

**通訊協定**必須與你要連線的 Broker 監聽器相符。請向你的 Kafka 管理員確認該用哪一種。

- `PLAINTEXT`：不加密也不登入。常用於本機和測試叢集。
- `SSL`：流量以 TLS 加密。搭配用戶端憑證時即為 mTLS。
- `SASL_PLAINTEXT`：以使用者名稱和密碼登入，不加密。
- `SASL_SSL`：透過 TLS 以使用者名稱和密碼登入。

變更通訊協定時，表單只會顯示該通訊協定需要的欄位。

<a id="sasl"></a>

## SASL

使用 `SASL_PLAINTEXT` 和 `SASL_SSL` 時，請填寫三個欄位：

- **SASL 機制**：`PLAIN`、`SCRAM-SHA-256` 或 `SCRAM-SHA-512`。可用哪一種由叢集決定。
- **使用者名稱**。
- **密碼**。密碼會儲存在系統金鑰儲存區，而不是設定檔中。請參閱[密碼](connections.md#passwords)。

SCRAM 從不傳送密碼本身。`PLAIN` 會原樣傳送密碼，因此透過 `SASL_PLAINTEXT` 時，密碼會以明文傳輸。對於不在你電腦上的叢集，請盡可能使用 `SASL_SSL`。

<a id="tls"></a>

## SSL 與受信任的 CA

使用 `SSL` 和 `SASL_SSL` 時，表單會新增 TLS 設定。

**受信任的 CA 憑證**是簽署 Broker 憑證的憑證授權單位（CA）的憑證。如果作業系統已信任此 CA，請留空，此時會使用系統根憑證。否則請輸入檔案的完整路徑，或按一下**瀏覽…**，選擇檔案後會出現 **CA 格式**欄位。若為 PKCS#12 和 JKS，還會有**信任儲存區密碼**欄位。

**驗證主機名稱**預設為開啟，它會檢查 Broker 憑證是否為你所連線的主機名稱核發。請只在測試環境中關閉，例如 Broker 使用其他名稱的自我簽署憑證時。

<a id="mtls"></a>

## 用戶端憑證（mTLS）

如果 Broker 以憑證驗證用戶端，請開啟**用戶端憑證（mTLS）**。憑證和金鑰由你的 Kafka 管理員核發。接著填寫：

- **用戶端憑證**：憑證檔案的路徑。
- **用戶端憑證格式**：PEM、PKCS#12 或 JKS。
- PEM：**用戶端私密金鑰**，即私密金鑰檔案的路徑；如果金鑰已加密，還需填寫**金鑰密碼（若已加密）**。
- PKCS#12：**金鑰庫密碼**。
- JKS：**金鑰庫密碼**；如果金鑰有自己的密碼，填寫**金鑰密碼（若不同）**；如果儲存區中有多個金鑰，填寫**金鑰別名**。

路徑必須是絕對路徑。每次連線時都會讀取這些檔案，因此憑證更新後只需重新連線。應用程式會檢查金鑰是否與憑證相符，以及憑證是否已過期。

常見的情況是 Kubernetes 中的叢集，用戶端 Secret 中包含 `tls.crt`、`tls.key` 和 `ca.crt`。將它們存成檔案，選擇通訊協定 `SSL`，將**受信任的 CA 憑證**設為 `ca.crt`，再將 `tls.crt` 和 `tls.key` 當作 PEM 用戶端憑證和金鑰使用，密碼留空。

<a id="certificate-formats"></a>

## 憑證格式

Glafira 可讀取三種格式。格式會依副檔名自動選擇；請在格式欄位中確認，必要時加以變更。

- PEM：以 `-----BEGIN` 開頭的文字檔。副檔名為 `.pem`、`.crt`、`.cer`、`.key`。用戶端憑證的金鑰是另一個檔案。受信任的 CA 也可以是二進位 DER 憑證。
- PKCS#12：包含憑證和金鑰的二進位儲存區。副檔名為 `.p12`、`.pfx`。
- JKS：Java 金鑰庫。副檔名為 `.jks`、`.keystore`、`.truststore`。

有兩類檔案需要先轉換：

- 不支援 JCEKS 儲存區。請將它轉換為 PKCS#12：

```bash
keytool -importkeystore -srcstoretype JCEKS -srckeystore client.jceks -deststoretype PKCS12 -destkeystore client.p12
```

- 以舊式演算法（RC2、3DES）加密的 PKCS#12 儲存區可能無法開啟。如果應用程式回報舊式演算法，請以 AES 重新建立檔案：

```bash
openssl pkcs12 -export -keypbe AES-256-CBC -certpbe AES-256-CBC -in tls.crt -inkey tls.key -out client.p12
```

<a id="passwords"></a>

## 密碼

SASL 密碼以及金鑰和儲存區的密碼會儲存在系統金鑰儲存區：macOS 上是鑰匙圈，Windows 上是認證管理員，Linux 上是 Secret Service。這些密碼絕不會寫入連線設定檔、匯出檔案或診斷壓縮檔。

編輯已儲存的連線時，密碼欄位是空白的，並顯示「**留空則維持不變**」。將欄位留空可保留已儲存的密碼，輸入新密碼則會取代它。若要刪除已儲存的憑證密碼，請勾選欄位旁的**移除已儲存的密碼**。儲存時，連線不再使用的密碼會被刪除，例如將通訊協定切換為 `PLAINTEXT` 之後。

如果應用程式無法存取金鑰儲存區，儲存時會顯示錯誤。在 Linux 上，請確認你的工作階段中有 GNOME Keyring、KWallet 或其他 Secret Service 提供者正在執行。

<a id="environments"></a>

## 環境與正式環境

**環境**用於標示連線：`local`、`dev`、`test`、`stage` 或 `prod`。環境會以彩色標籤顯示在面板中的名稱旁，讓你隨時知道自己正在使用哪個叢集。

`prod` 會加上保護。在正式環境連線上進行任何變更，例如建立主題、傳送訊息、重設偏移量或啟動消費者工作階段，都會要求你輸入連線名稱。在任何連線上刪除和清除時，都會要求輸入物件名稱（刪除多個主題時要求輸入數量）；在正式環境上則兩者都要輸入。這些確認會顯示在應用程式視窗內。

新的正式環境連線預設為**唯讀**。如果需要進行變更，請取消勾選該核取方塊。

<a id="read-only"></a>

## 唯讀

**唯讀**會封鎖所有變更叢集的操作：建立、變更、清除和刪除主題，傳送訊息，重設偏移量，刪除群組，以及啟動消費者工作階段。這些操作的按鈕會隱藏或停用，應用程式核心也會拒絕這類操作。瀏覽和讀取仍可使用。面板中名稱旁的鎖頭圖示表示唯讀連線。

只需要查看資料時，特別是在共用叢集上，請使用此模式。唯讀是應用程式內的保護，無法取代 Kafka 中的存取權限（ACL）。

<a id="folders"></a>

## 資料夾

資料夾可用來分類連線，例如依專案或依環境。資料夾可以巢狀放置。

- 若要在最上層建立資料夾，請按一下面板標題列中的 `+📁`（**新增資料夾**）。若要建立子資料夾，請開啟資料夾選單，選擇**新增資料夾**。輸入名稱後按 `Enter`，或按 `Esc` 取消。
- 若要開啟資料夾選單，請按一下資料夾列上的 `⋯`（**更多動作**），或在資料夾上按右鍵。選單中有**重新命名**、**刪除**，以及匯出和匯入指令。
- 只能刪除空的資料夾。請先移動或刪除其中的連線和子資料夾。
- 同一層中的資料夾名稱不得重複，長度最多 100 個字元。

若要移動連線，請將它拖曳到資料夾上，或拖曳到另一個連線上，放在該連線之前。若要移到最上層，請將它放到面板標題列或清單下方的空白處。也可以在連線表單中選擇**資料夾**；選擇「**（根目錄）**」表示最上層。資料夾的拖曳方式相同。將資料夾放到另一個資料夾的上緣，即可放在該資料夾之前。資料夾無法移到自己的子資料夾中。

按一下資料夾名稱可以收合或展開。應用程式會記住哪些資料夾已收合。使用樹狀結構上方的**篩選連線**，可依名稱尋找連線和資料夾。符合的資料夾會連同其所有內容一起顯示。

<a id="export"></a>

## 匯出

匯出會將連線和資料夾儲存成檔案，例如分享給同事或移到另一台電腦。

1. 若要全部匯出，請開啟面板標題列選單 `⋯`，選擇**全部匯出…**。若要匯出一個資料夾及其子資料夾，請在該資料夾的選單中選擇**匯出資料夾…**。
2. 選擇檔案的儲存位置。建議的名稱為 `glafira-connections-<date>.glafira-connections.json` 或 `<folder>.glafira-connections.json`。

檔案儲存後，面板會顯示其中包含多少連線和資料夾。

檔案中包含連線設定和資料夾結構，但不包含密碼或機密屬性。憑證檔案也不會包含在內，檔案中只保留它們的路徑。主機、使用者名稱和路徑會以純文字儲存，因此請只與可以看到這些資訊的人分享檔案。

<a id="import"></a>

## 匯入

1. 開啟面板標題列選單 `⋯`，選擇**匯入…**。若要直接匯入到資料夾，請在該資料夾的選單中選擇**匯入到這裡…**。
2. 選擇 `.glafira-connections.json` 檔案。會開啟**匯入連線**對話框。
3. 在**匯入到**中選擇新資料夾和連線要放到哪裡。「**（根目錄）**」表示最上層。
4. 保持開啟**更新現有連線**，即可用檔案中的內容更新已存在的連線。關閉此選項則會保留它們原樣。
5. 檢查預覽後按一下**匯入**，或按**取消**關閉對話框而不做任何變更。

對話框中每次變更後，預覽都會更新。預覽會顯示總數和可展開的清單：**新增**、**將更新**、**未變更**和**已略過**，並列出每個略過的連線的原因。

應用程式比對檔案和你的連線的方式：

- 連線依內部 ID 比對，而非依名稱。如果檔案中有同一個連線，該連線就視為已存在，例如它是從這台電腦匯出的，或先前從同一個來源匯入過。
- 更新的連線會套用檔案中的設定，但你的密碼和它在樹狀結構中的位置會保留。
- 已存在的資料夾不會被重新命名或移動，檔案中的新連線仍會放入其中。
- 如果新連線與同一資料夾中的另一個連線同名，會加上編號，例如 `kafka-dev (2)`。
- 這個版本的 Glafira 不支援的連線，或額外屬性中含有機密的連線，會被略過。

如果在這台電腦上找不到憑證檔案，預覽也會發出警告。檔案中沒有密碼，因此匯入後，面板會顯示有多少連線需要輸入密碼。請開啟這些連線，逐一輸入密碼並儲存。
